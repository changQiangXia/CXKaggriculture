# 运行时扰动的系统性失败（2026-09-27，四次实验的统一解释）

## 1. 四次同类实验，全部判负（同世界自身经济）
| 实验 | 改动性质 | 是否改变手持物品 | 实测 |
|---|---|---|---|
| `arch_fertloop` | 空转回合 → 收肥/施肥/取肥 | **是** | −1,810（t=−2.77） |
| `arch_nofertwc` | 压制低价值施肥 → PASS | **是**（肥料滞留） | −3,135（t=4.66） |
| `harmir` 收割填补（早前） | 空转回合 → HARVEST | **是** | 池内 +3.5k / 线上 −146（同漂移量级） |
| `arch_carefill` | 空转回合 → **CARE（物品中性、位移中性）** | 否 | **−465（t=9.88）** |

`carefill` 是最干净的对照：CARE 不改变手持物品、不改变位置、不改变市场，
却在 160 局里输 465/局，且**中位数完全相同**（+156,581），
差异集中在少数局 ⇒ 不是"经济账"问题，而是**扰动传播**问题。

## 2. 机制解释（与 Ahmed 的 RNG 洞察一致）
官方引擎里 **weed 抽取发生在下一次 shop 抽取之前**：任何改变"我方占据的 tile/动作序列"
的改动都会改变后续 RNG 流（杂草生成、商店解锁），从而使整局走向分叉。
我们的磁带是**逐格逐回合手工编排**的，PASS 往往不是"空闲"而是
"在该格等待下一步计划"（例如等待作物成熟/等待市场窗口）。
把它改成任何动作（哪怕是最无害的 CARE），都会：
1. 改变该单位的后续状态（哪怕不改物品，也会改 `cared_today` 之类的引擎标记）；
2. 进而改变 RNG 流与对局展开；
3. 在少数局造成数百到数千的损失，且**没有对应的收益**能覆盖它。

## 3. 结论（写进 P5 纪律）
**运行时"见缝插针"式改动在这个 agent 上已被四次实验否证**，
包括物品中性、位移中性的 CARE。后续只做两类改动：
1. **磁带级（计划级）改动**：直接改写 route，让计划本身更忙/更大，
   位置与物品流整体自洽，不含"事后插动作"；
2. **纯参数改动**：只调常数（但已知 CAP/CH_SHED/SLOT_MARGIN 的调整都是负向）。
⇒ 这也解释了为什么"那 124 个终局空转回合"不能靠补丁吃掉：
它们要么是计划的等待点，要么改写必须与整个终局计划一起重排。
