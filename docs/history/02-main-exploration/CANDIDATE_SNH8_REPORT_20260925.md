# archplus 深挖结项：OR2 卖单窗口 48 → 8（2026-09-25）

## 0. 一句话

把 archplus 里 OR2 层"把未来计划卖单提前到本回合"的窗口 `_OR2_SN_H` 从 **48 改到 8**，
在**两个互不相交的种子块**上分别拿到 **+536**（33–48，t=+7.6）和 **+543**（57–80，t=+10.4）的配对增益；
叠加四个小正项后为 **+581 / +598**，并且公开池、新公开池、难例闸全部不退化。
候选已打包（**未提交**）：`candidate_snh8.tar.gz`、`candidate_snh8_combo.tar.gz`。

## 1. 方法（新增工具，可复跑）

| 工具 | 作用 |
|---|---|
| `knob_patch.py` | 把 arm 源码里某个模块级常量的**所有**赋值替换掉（后赋值覆盖先赋值，全部替换才无歧义），写成一个变体文件 |
| `knob_sweep.py` | 单旋钮扫描：每个变体跑同一强池、同种子、**双座位**，与基线逐场配对，输出均值差 / SE / t / 胜平负 |
| `layer_census.py` | 层活跃度普查：跑几局后比对模块里所有 `*_REPORT/_STATS` 计数器的变化，找出**从不触发**的层 |
| `mock_open_family.py` | 按真实语料里对手 step-0 下单构造的"对手开局族"模拟池（9 族） |
| `corpus_rival_families.py` / `corpus_opening_states.py` | 从真实 replay 语料抽出对手开局族/开局状态与我们胜负的关系 |

基线：`panel_runs/sweep/BASE_archplus_33_48.json`（archplus 原版，seeds 33–48，强池 128 局）。

## 2. 层普查：archplus 里有 11 个层是死层

6 个对手（HL / icefire / v61 / v48 / haideptry / 镜像）× 36 局，**全程零触发**的层：

```
_CT_REPORT, _OV_REPORT, _PG_REPORT, _ROOM_STATS, _SL_REPORT, _V233_REPORT,
_V92_Q_REPORT, _VE_REPORT, _VT_REPORT, _Y_REPORT, _v9_racegate_report
```

逐个读闸门后的判读：

* `_OV/_ROOM/_SR/_PG/_Y` —— 都是"棚子快要溢出时提前卖"的**同级冗余**：现在的 SHEDROOM 层已经
  让 `shed+carried` 常年不过 99，所以这些层永远等不到条件（零触发 = 无收益，也说明棚管理已经紧）。
* `_V233/_SL` —— 六羊项目的一工人紧凑服务，闸门要求 `_SL_TILES` 那 6 格的精确布局，我们现在的路线库不产生该布局。
* `_V92_Q` —— 预测器的 Q 版本，被 P 版本取代（P 每局触发 100–480 单位）。
* `_VE/_VT/_v9_racegate` —— 预算/日门控的旧版本，条件在我们的打法下永不满足。
* **`_CT` —— 唯一"有战略含义"的死层**：它是一张 `(对手现金, 市场小麦库存)` → 反制下单表，
  但键值（`979.0/33.0` 现金、`9989/9990` 库存）是旧 meta 的手工产物，真实语料里 281 局只命中 1 局。

## 3. 真实语料的对手开局族（281 局）

`corpus_rival_families.py` 按对手 step-0 实际下单分类：

| 对手开局 | 局数 | 我们胜率 | 平均分差 |
|---|---|---|---|
| `BUY 20 / SELL 15 / SEED 1` | 82 | 67.1% | +318 |
| `BUY 20 / SELL 15` | 38 | 57.9% | +350 |
| `BUY 5 / SEED 1` | 16 | 81.2% | +857 |
| **`BUY 10 / SELL 10 / SEED 1`（及变体）** | **18** | **22.2%** | **−5,276 / −241** |
| **`BUY 8 / SELL 8 / BUY 5 …`（= 我们自己的白手开局族）** | **12** | **0.0%** | **−3,426** |
| `BUY 7 / SELL 2` | 12 | 75.0% | +983 |

两条结论：

1. 老底座（snh48）**只输给"同类白手往返"族**；这正是 archplus 的开局谱系压制设计目标。
2. 对手 step-1 现金分布：**227/281 在 2900–2920**，只有 **25/281 在 ≥3000**——
   而 archplus 的开局判别器阈值 `_O_DISCRIM_THRESHOLD=2950` **只对那 25 局生效**。
   阈值本身扫 2800/3100 都是噪声级（+63 SE=197 / +34 SE=33），说明**判别器的信息量不足**，
   想扩展必须换更细的状态键（市场小麦库存等），不是挪阈值。

## 5. 主发现：`_OR2_SN_H` 的完整曲线（都是配对，n=128）

⇒ 有效的不是"买小麦"，而是**占槽位的洗单**；只买不卖会把价格砸在自己手里。
