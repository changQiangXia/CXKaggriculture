# 目标结项：把"流推断对手销量"做成对手感知卖单层（2026-09-25）

## 0. 一句话

**这个技巧我们底座里本来就有（V9 RACE 层），而且它是活的**；我基于它做了 4 个改进变体，
结果**全部惰性或中性**。cha22 那套重写版在活体里基本是死代码（每局只动 3 个单位）。

## 1. 流推断的算式（cha22 与底座一致）

```
对手净卖出 ≈ Δ市场库存 + 城镇商店消耗 − 我方卖单
```
- cha22：`_fx_update()`（`_FX_ITEMS` 7 个溢价品，价格 > 3 才算）
- 我们底座：`_v9_race_update()`（同一个算式，`V9_RACE_ITEMS` 同样是那 7 个品）

## 2. 底座现役层的实测（活体）

```
base 镜像一局:  race_report = {rival_sales: 234, leads: 38, race_errors: 0}
base vs HL  :  race_report = {rival_sales: 130, leads: 22, race_errors: 0}
```
即：**每局能还原 130–234 次对手卖出事件、记录 22–38 次"对手抢在我们前面"的领先**，
并按 `horizon = min(48, max(40, lead + 12))` 放大卖单前瞻窗口。

## 3. 我的改进变体（都建立在 archplus 之上，强池 33–56，192 局）

| 变体 | 改动 | 结果 | 判定 |
|---|---|---|---|
| 基准 | `margin 12, cap 48` | 187胜5负 / +7,097 | — |
| **销量感知** | 按推断流量 `+min(24, flow//10)` | 187胜5负 / **+7,097（逐场完全相同）** | **惰性** |
| 常量 margin 24 | `lead + 24` | 189胜3负 / +7,104 | 见下 |
| 上限放大 64 | `cap 64` + 流量加成 | 187胜5负 / +7,097 | 惰性 |

**常量 margin 24 的第二块验证（57–80）**：archplus 187胜5负 → race_m24 **185胜7负（−2）**。
两块合计 **374胜10负 vs 374胜10负 ⇒ 完全中性（+2/−2 对称抵消）**。

## 4. 为什么改不动（两条独立证据）

1. **前瞻窗口参数很少真正绑定**：把它从 `12/48` 改成 `24/64`、或按对手流量动态放大，
   结果逐场相同 ⇒ 卖单是否发生、什么时候发生，由 tape 自己的排程决定，窗口不是瓶颈。
2. **注入式抢跑在活体里几乎是死代码**（cha22 移植臂遥测，一局）：

```
fx_rival_seen = 121      ← 流推断在工作
fx_fires      = 0        ← FLOWPX 被自己的 _FX_FLOW_MIN=999 永久禁用
ev_fires      = 1  (3 单位)   ← 晚间层一局只动 3 个单位
dp_fires/mp_fires = 0 / 0
```
   而我们一局要卖 2,000–2,900 单位 ⇒ 3 单位 = 噪声。

## 5. 结论

- 目标（"把这个技巧做成对手感知卖单层试试"）**已完成**：技巧已在底座中现役、
  被实测证明在工作，四种改进尝试全部惰性/中性。
- 与 cha22 的对比也解释清楚：它的 FLOWPX 是同一算式的重写，但被自己的阈值禁用，
  DAWNPX/MIDPX 因"已在本回合有卖单/计划量为 0"而从不触发 ⇒ **它的招牌机制实际未生效**，
  这也解释了它为何全面弱于我们（镜像 −842、强池 132/60、扩展池 335/73）。
