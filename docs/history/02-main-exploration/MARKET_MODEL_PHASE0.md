# 市场结算律 Phase 0 逆向结果（bit-exact 对拍已钉死）

## 已确认的事实（kagsim 最小对拍实验，seed 12345）

### 初始状态
- 9 个商品库存全部 = **10000**（=I0），价格 = 各商品 base。

### 逐单位结算（最关键）
- 每步按 **slot 0..9** 依次结算；同一 slot 内 player0 与 player1 的订单
  **逐单位交错**（p0 先 1 单位、p1 再 1 单位、交替直至耗尽）。
- **SELL**：每单位 `money += p(I)`，然后 `I += 1`（受仓库库存限制，缺货整单跳过）。
- **BUY_PRODUCT**：每单位先 `I -= 1`，再 `money -= p(I)`（受现金限制，钱不够
  自动部分成交——实测 BUY 100 只买到 95，因为价格随库存下降一路上涨）。
- 即：卖按"搬动前价格"收款，买按"搬动后价格"付款；价格 = int(round(f(I)))，
  底价 1。

### 日耗（demand tick）
- 在 step 0 与每个 day 的第一步（step 24,48,...）的**市场结算之后**，
  除 FERTILIZER 外每个商品 `I -= 1`。30 天共 -29，价格自然缓升。

### 固定价格订单（不动市场库存）
- HIRE = 1；BUY_SEED 麦10/萝卜20/番茄50/草莓100/甜瓜80；
  BUY_ANIMAL 鹅300/牛400/羊500；BUY_LAND 1000/2000/4000 按已解锁象限数。

### 已验证的价格曲线（与引擎对拍吻合）
- WHEAT: 25；低于 I0 `25+√(10000−I)`，高于 I0 `25−0.834·ln(1+I−10000)`。
- STRAWBERRY: 120；低于 `120+8.4·√(10000−I)`，高于 `120−1.92(I−10000)`。
- MELON: 250；低于 `250+8.76·ln(1+10000−I)`，高于 `250−0.01(I−10000)²`。
- FERTILIZER: 100；低于 `100+0.2(10000−I)`，高于 `100−0.2(I−10000)`；
  无日耗、无开市 tick。

## 待办（Phase 1）
- 已发现"日耗"不是确定性 tick，而是 **RNG 驱动的随机抽取**（无订单时 EGG 减少
  发生在 77/93/105/125…等不规则步），期望值 = 每商品 1/天 + 每家店菜单；
  market RNG 未包含在提取语义中，故库存的**实现路径**无法 bit-exact 对拍。
- 因此验收口径修正：**现金（不受 RNG 影响）目标 bit-exact；库存目标
  "结算分量 bit-exact + 需求统计期望精确"**。

## 【重要更正 2026-09-24】需求不是 RNG，结算律有多处语义错误
读官方引擎源码（kaggle_environments/.../kaggriculture.py）后推翻两处旧结论：

1. **需求是确定性函数**（旧"RNG 随机抽取"结论作废）：`_town_consume`
   - step%4==0：每家已解锁商店实例消费其菜单（单品店每项 2，否则每项 1）；
   - step%24==0：镇中心每非肥料商品消费 1；
   - 商店解锁本身是 `random.Random((seed*1_000_003)^day).choice`，但商店列表
     在观测里可见，故需求可完全重建。旧的"统计期望"口径不需要了。
2. **结算语义五处修正**（旧模型全部有偏差，是 4.5k 现金残差的来源）：
   - 配对 BUY_PRODUCT 报价用**递减后库存** p(I−1)（官方注释：同价往返净零）；
     旧模型用快照 p(I)，恰是 step-0 残差 −4 的来源；
   - BUY_PRODUCT 仅 WHEAT/FERTILIZER 合法，且受 shed 容量 100 门控（装满即拒）；
   - 地板价卖单（price==1）**不增加市场库存**（旧模型每卖必 +1）；
   - HIRE 成本 = farmHandCostMult×fib(hires_today)，fib=1,1,2,3,5…；用当日
     已雇人数而非手数（旧模型用 len(hands)+1）；
   - **空订单是槽位占位符**：两个玩家的市场列表必须按原始槽位对齐，过滤空
     列表会让 BUY/SELL 在锁步里错误交错（±1~8 残差主源）；
   - 价格取整是 Python 银行家舍入 int(round(v))，不是四舍五入。

## 新钉死的规则（2026-09-24 追加）
- HIRE 边际成本 = **斐波那契序列** fib(hands+1)：1,1,2,3,5,8,13,21…；
  工人是**日结劳力**（每天重置、需每日重雇）。
- 需求统计最小二乘解（4800 个日界样本，干净到小数点）：基础 -1/商品/天
  （肥料除外），店铺菜单 = BAKERY{麦,蛋}、BRUNCH{麦,蛋,草莓}、ICE{奶,草莓,麦}、
  PIZZA{奶,番茄,麦}、PET_CAFE{萝卜×2}、SMOOTHIE{奶,草莓}、YARN{羊毛×2}、
  FARMERS_MARKET{萝卜,草莓,番茄,麦}。
- 现金对拍：145k → 4,548 不匹配（96.9% 收敛）；残余集中在 ±1~4，为日界
  需求抽取与结算的取整次序交互（干净受控用例全部精确命中）。

## 战略含义（立即可用）
- 市场是一个"先到先得"的逐单位队列 + 凸价格面；**单笔大单的收入 = 价格曲线
  下的离散面积**，甜瓜类平方惩罚下存在单次最优抛售量（≈91）——超量抛售总现金
  反而下降。
- 变现问题由此成为完全指定的最优控制：每步在 10 槽里分配各商品卖出量，对抗
  对手插队与日耗。下一步做 1-D 最优变现 + 对手卖出流预测（Phase 2）。

## Phase 2 第一次实验被证伪（2026-09-24，21 局最新败局反事实）

### 工程修复
- `v54_sweep3_snh48_realize.py` 的 loader 拾取 bug 已修：新包装器 `agent` 在
  模块命名空间里位置早于 `_REALIZE_PARENT`，kaggle loader 的
  `[v for v in m.__dict__.values() if callable(v)][-1]` 拾到旧 `_d27_agent`。
  末尾按本仓库既有惯例加 `agent = globals().pop('agent')` 把名字挪到末尾。

### 口径钉死
- 官方 `kaggle_environments/envs/kaggriculture/kaggriculture.py` 明写：
  `s.reward = float(obs0.farms[s.observation.player]["money"])` ——
  **终局只算现金，shed 库存价值为 0**（kagsim 行为一致，已实验复现）。
- 因此"持有到终点"的 1-D 结论在真实打分下不成立；任何变现策略必须
  在 step ≤ 718 前把所有可售库存卖完，否则直接归零。

### 反事实结果（21 局，base vs realize，tape 对手）
- delta mean = **-94,212**，min -146,800，max +3,103；20/21 灾难性负，
  唯一正局 +3,103（base 仍为负 → 无相位翻正，sign flips = 0）。
- telemetry 证实控制器机械上生效：平均 68 个卖出回合 / 1,470 单位。
- 终局 shed 每局都被挤到上限 100。

### 归因（112417760 局逐项拆解）
- 终局滞留 shed 按终价只值 **4,190**（麦 41 + 萝卜 39 + 草莓 13 + 羊毛 3 +
  肥料 4），占 -146,800 的 ~3%。**滞留不是主因。**
- 主因是三个复合通道：
  1. **卖错商品**：缺现金时按"持有增益最小优先"卖 WHEAT/CARROT 低价货，
     把 tape 计划好的高价货 SELL 全剥掉 → 高价货永远没变现；
  2. **挤满 shed 上限 100**：剥掉卖出后库存只进不出，生产拾取被仓库上限
     卡死，生产管线停工；
  3. **与 ER 前插层互斥**：v1 把 d23-29 的前插卖单也剥了，等于撤销了
     base 的终盘抗 dump 机制。

### 结论与 Phase 2 v2 方向
- "少卖 + 卖最便宜货" 策略被干净证伪；不是参数问题，是模型边界错误：
  1-D 模型缺了两项——现金终局计分、共享库存下对手卖出流对价格的下压。
- 修正后的最优控制目标：**保持总卖出量与买入资金流不变，只重排卖出时机**
  （把 tape 计划卖单在对手 dump 前提前结算、在需求抬价段后置），并且
  step 718 前强制清仓。这是 base ER 层 d23-29 窗口的全场普适化版本。

## Phase 2 证据链收口：变现空间已到帕累托前沿（2026-09-24）

### 通道归因（attribution2.py，bit-exact 逐单位记账，21 局残差 ≤ 数十）
- 21 局败局总钱差 +48,831；**卖出通道总赤字 +145,596，19/21 局卖出收入
  落后于对手**；买入与固定成本通道只是部分对冲。
- 逐商品拆解（有效成交口径）：双方各商品成交量与每单位均价几乎相等
  （WOOL 136.1 vs 135.3、STRAWBERRY 109.2 vs 107.7、MELON 200.8 vs 195.7），
  即**卖出时机本身已打平**；卖出赤字 95% 来自 WHEAT 成交量差

- 终局 shed 双方全空：无滞留泄漏可修。

### 三个候选机制逐一证伪 / 中性（21 局 tape 反事实，rz2 开关）
1. **ER 前插窗口扫参**（er_from∈{384..528}×er_to∈{696,711}×dump≥{3,4,6}×
   min∈{2,4}，96 组）：最优 504/696 合计仅 **+109**，0 翻正 0 新增负局。
   早期（day17-18）确实存在不对称前插事件，但窗口前移捕不到净收益。
2. **小麦 wash 砍单**（rz2_wheat_px∈{38..44}）：th=38 灾难（砍掉盈利支撑，
   单局 -16k~-31k）；th=44 完全中性（21 局合计 -1）。小麦 wash 本质是
   **抬价支撑公共品**：我方买入抬高共享麦价，喂大我方生产卖单；只有镜像
   双支撑时才是浪费（112459470 双方各亏 3.7k/4.6k）。
3. **持有+卖最便宜**（v1）：-94k（前文已证伪）。

### 四门终审（rz2_gate.py：ER 504/696 + wheat_cap 44，8 进程 ~900 局）
- Gate1 257 池：cand 0.9216 = base 0.9216，**不退化**（0.96 目标是 GA 线的
  绝对门槛，base 自己也不达标）。

### 结论
- 三个变现机制全部证伪或中性：**在 21/107 败局语料上，最优变现控制器
  ≈ base 本身**（v54 herdfix + d27 + ER）。任何非零改动都会在 tape 上
  赢一点、在镜像赛上输一点，"107 零负 delta + 镜像 90 零负板"只能由
  base 自身严格满足。
- 剩余真实预算：小麦支撑的**自博弈搭便车**（对手大举抬价时我方减仓、
  对手不抬价时我方抬价），单局 ±4k 但方向条件性强；以及归因里占比更大的
  **固定成本/产量结构差**（雇佣节奏、小麦产能），那属于生产 tape 规划，
  不在"变现控制器"范围内。

## Phase 2 最后两条腿的证伪（2026-09-24 追加）

### 小麦自博弈搭便车（对手买入流条件砍单）
- 实现 rz2_wheat_rival（λ）：用共享库存一阶差分 + 期望日耗重建对手上一步
  小麦净买入流，对手净流入 ≥ λ 且麦价 > θ 时砍我方 BUY_PRODUCT WHEAT。
- 关键陷阱已钉死：回放 `steps[i]['observation']` 是第 i 步**之后**状态，
  决策时刻只能看到上一步的对手流；而镜像局双方**同回合同量**买入，决策
  时刻不可见。λ∈{20,40,60}×θ∈{40,42,44} 全部退化为纯价格阈值结果
  （与 λ 无关），中性。**同回合镜像买入在信息论上不可提前观测，搭便车
  规则结构上失效。**

### 卖出抢跑（速率预判）
- 神谕预算（21 局）：我方"跟卖"事件 1019 次，最大可争取 +90,472
  （MELON +31.5k、WOOL +30.5k、STRAWBERRY +13.9k、MILK +12.1k），远超
  总钱差 48.8k——但这是"提前 1 步知道对手 dump"的上界。
- 可实现版本 rz2_pre（对手近 W 步净卖出 ≥ λ 时，把 tape 未来 K 步卖单
  提前到 slot 0）：12 组参数全部**负收益**（-160 ~ -765，0 翻正）。
  原因：速率触发时价格已被对手砸低，抢跑等于卖在坑里；base 的 tape 本身
  已经等需求恢复再卖，是局部最优。
- 结论：**神谕预算不可达**（需要逐事件预知对手 dump 步），可实现的
  "对手卖出流预测"不如 base 的既定节奏。对手卖出流预测腿闭环。

### 变现线最终结论
- Phase 1 结算律 bit-exact 复现 ✅；Phase 2 在 21/107 败局语料上解出：
  **最优变现控制器 = base 本身**；四条原创机制（持有、前插窗口、小麦
  价格/搭便车、卖出抢跑）全部证伪或中性，证据见各节反事实表。
- Phase 3 四门的"107 零负 delta + 镜像 90 零负板"只能由 base 自身满足；
  任何非零改动都在 tape 赢一点、镜像输一点（实测 5 块负板、2 个负 delta）。
  剩余唯一未开发预算在**生产/固定成本结构**（雇佣节奏、小麦产能、买端
  时机），超出"变现控制器"的目标边界，需用户决定是否转移目标。
