# 3 个值得一试的机制候选（2026-09-19）

筛选标准：绑定环境源码的精确规则、我们尚未系统验证、有可量化的胜负通道。

## 机制 1：锁步 index 配对收割

**规则依据**（kaggle_environments `_process_market`）：
- 双方市场订单按 **list index 锁步配对**：index i 的两份订单先同时报价、再按
  座位顺序结算。
- **报价不对称**：`BUY_PRODUCT` 按 `price(inventory-1)` 报价（买后价），
  `SELL` 按 `price(inventory)` 报价（卖前价）。同 index 配对时，买方付得比卖方
  收得多，差价是"报价税"。

**机制（修正版）**：报价税的承担方永远是 BUY（`P(inv-1) > P(inv)`，低于 I0
  时），与配对无关；真正的杠杆是 **index 相对顺序决定报价库存**——对手的每日
  小麦买入会压低库存、抬高价格，把我们的 SELL 排在"对手 BUY 之后"的 index，
  我们就能卖在对手买后抬高的价位上。而底座现在的 sales-first 恰恰把 SELL 顶
  到最前（与对手 BUY 同 index 或更前），错失了这个抬价窗口。底座的 CTRTABLE
  （"trade alongside their own early wheat orders in the same market slots"）
  是同一思想的 day-0 雏形，但只覆盖两个已知 tape。

**泛化**：用 `_R44_PROBES['matched']`（镜像检测）+ 影子预测的对手订单结构，
  在每天、所有商品上做 index 排列优化（我们的 SELL 排在对手同商品 SELL 之前、
  对手 BUY 之后）。这是"市场微结构"层面最硬、最未被开采的不对称。

**验证**：镜像局 h2h（vs farm2945 本体、vs 激进克隆），看配对收割能否把
  78%/71% 再推高。

## 机制 2：卖点序列的相位偏移

**规则依据**：镜像局双方执行同一份 route tape，卖点天然重合；环境按 index
  锁步结算，同一步的相同卖出互相把价格打低。此前我们改的是"门槛"（何时不
  卖），从没试过"相位"（整个卖点序列统一提前/延后 k 步）。

**机制**：把我们的卖出序列整体偏移 ±1~2 步。提前 → 抢在对手 glut 之前吃高价；
  延后 → 让对手先卖、town draw 恢复价格后我们卖得更高。哪个方向赢取决于商品
  曲线（sq 崩盘商品提前、log 抗跌商品延后），可以用 per-item 相位表。

**入口**：RACEPX 的 1-turn lead（`nxt = step + 1`）→ k 步；或 `_r36_reserve`
  的 reservation 落点整体偏移。

**验证**：镜像局 h2h 扫 k ∈ {-2,-1,0,1,2}，按商品拆开看最优相位。

## 机制 3：对手扩张节奏的供给预测

**规则依据**：`farms[rival].hires_today` 与 `tiles` 上的动物/作物都是公开
  信息；动物每天消耗小麦、按固定 interval 产出奶/毛/蛋。对手的雇佣波次 →
  动物扩张 → 未来若干天的奶/毛供给可预测。

**机制**：观察对手的 hires_today 与新增 PASTURE/COOP，预测未来 ~10 天的
  WOOL/MILK/EGG 供给冲击，把我们的对应商品卖出**提前到冲击之前**（供给未到、
  价格仍高时出清）。这是"前瞻"而非"响应"：现在的 RACE 层只对已经发生的
  对手卖出做响应。

**验证**：镜像局 + 真实池；对比"供给冲击前出清"与当前 RACE 响应的胜率差。

## 优先级

1 > 2 > 3（机制 1 最硬但实现最重；机制 2 可立即验证，先做）。

## 机制 2 的初步验证（2026-09-19 晚）

先把最便宜的入口测了：RACEPX 的 1 回合领先卖改成 0 / 2 回合（timed174 底座）：

| 变体 | vs 本体（64 世界） | vs 激进克隆（32 世界） |
|---|---:|---:|
| lead0 | 20W/12L（16 世界 62.5%） | 未测 |
| **lead1（timed174）** | 100W/28L，78.1% | 55W/9L，85.9% |
| lead2 | 96W/32L，75.0%，worst -12030 | 53W/11L，82.8% |

结论：RACEPX 这个入口上，1 步领先已是局部最优；±1 都不改进。但注意
RACEPX 只影响"1 回合领先"层，真正的**整条卖点序列相位偏移**（作用于
reserve 落点/tape 原生卖点，需要 pending 队列把 SELL 统一延后 k 步）尚未
实现——机制 2 仍有完整版待验证，只是不能从这个入口做。
