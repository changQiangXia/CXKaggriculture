### 2.2 第五个设计：`expansion_v4`（专属工人）——同样失败

设计：提前买地（day10/11）+ **多雇 3 个"专属工人"**（磁带只寻址它预期的工人数，多余的由 `hand_align` 填 PASS）
+ 只种最新象限 + 自带瓜种储备。

| 指标 | 结果 |
|---|---|
| day12 结构 | (42–52, **4 象限**)，仍低于基线 52–53 |
| 专属工人产出 | 种 9 / 浇 10 / 收 0（10 局） |
| AM 靶场 107 局 | **36/107 翻盘，均值 −6,935** |
| 配对差 | **−22,269/局（SE 1,306，t=−17.05），翻盘净 −41** |

⇒ 多雇 3 人 + 多买 2 块地 ≈ 7.2k 现金被抽走，磁带计划（雇工/种子/饲料）立刻挨饿；
新象限的边际产出（甜瓜 day20 后才收）远不足以补偿。

⇒ **"提前买第 4 象限"不是无益而是有害**：抽走 2,000–4,000 现金使磁带计划（雇工/种子/饲料）资金变紧，
而新象限又没人种——两头的成本都落在我们身上。

### 为什么 v1/v2 无效、v3 反而更差

1. **站立株数 = 长周期作物数**：小麦 2 天就割，补种再多也不涨"站立数"；甜瓜（10 天）才对，但空闲工人**很少刚好站在新地的空格上**（磁带路线都在旧象限），所以 v2 只补了 8.7 株/局。
2. **v3 的走路规划解决了覆盖率，却制造了冲突**：我们把甜瓜种在磁带**即将要用的空格**上，并消耗了磁带计划要用的瓜种 → 磁带的 PLANT 失败 → 站立株数掉到 35–46。
3. 要同时避免这两点，必须**知道磁带未来的格子/种子需求**（即拥有一个协调的生产规划器），这已超出"空闲时间填空"的范畴。

## 3. 与语料证据的一致性

* 上一轮已证：AM 260 局里"对手 day12 ≥70 株"只出现 **1/260**（4 象限 2/260），而我们与对手结构 91–94% 全等 ⇒ **该结构不是赢家特征**；
* 本轮进一步证明：**在现有架构内，即使主动提前买地，也堆不出 70+ 株**——瓶颈不是钱，而是**协调的劳动与种子分配**。

## 4. 结论与建议

| 判据 | 状态 |
|---|---|
| M2 象限半边（4 象限） | ✅ 达成（一次有界的提前买地） |
| M2 株数半边（≥70 株） | ❌ 未达成，四轮尝试后判定：需要**完整生产规划器**（协调劳动/种子/地块），即"无界重写" |
| 资金自洽 | ✅ 买入时现金中位 10.8k–14.9k，无未资金订单 |
| 更强候选 | ❌ 未产出（结构提升未转化为对局优势；v3 反而损害结构） |

**建议**：本 goal 的目标值（70 株/4 象限）已被两轮证据证明**既不是赢家特征、也在本架构内不可达**。
若要继续生产端，应改写为"**协调式生产规划器**"，但那等于从零实现农场调度（项目此前评估成本过高）；
替代方案仍是放开线上数据、从真实败局找新缺陷类。
