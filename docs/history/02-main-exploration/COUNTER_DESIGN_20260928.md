# 反制设计稿：市场是公开函数，打法是"时机 + 品类"（2026-09-28 23:30）

## 0. 一句话

价格是**存货的公开确定性函数**（源码里参数齐全），而存货 = 初始 + 双方卖出 − 商店消耗。
所以"抢卖"只是零和的位置争夺，**真正有增量的是两件事**：① 品类（对无商店需求的物品，
多卖一分钱都拿不到）② 商店消耗带来的"等待漂移"（对有商店需求的物品，早卖反而亏）。

## 1. 市场模型（来自官方 `kaggriculture.py`，非猜测）

```
price(inv) = base ± amp · f(|inv − I0|),   amp = target·base / f(T),   I0 = 10,000, 地板价 1
存货变化：玩家每卖 1 单位 → inv +1；每 4 步每个已解锁商店消耗 multiplier 单位；市中心每 24 步消耗 1。
```

## 2. 为什么"抢卖"不是答案（我们已实测过）

* 引擎是**逐单位锁步撮合**：同一步内双方单位**拿到同样的报价**。
  ⇒ 同一小时同时卖 = 平手；抢卖只在"比对手更早的步"才有意义。
* 我们已经扫过抢卖强度 `_OR2_SN_H`：**最激进档（1/2）在家族面板从 89.6% 崩到 74%**
  （`SCAN_PROTOCOL_OR2SNH_20260928.md`）。
  原因现在清楚了：一刀切抢卖对**有商店回收**的品类（牛奶/草莓/小麦）是亏的——
  等待本身有正收益（商店每 4 步消耗存货 → 抬价）。

## 3. 四个反制候选（按性价比排序）

### C1（首推）品类分化的卖法：按"商店需求 × 曲线形状"逐个物品设卖点

现状：`_OR2_SN_ITEMS = (MILK, STRAWBERRY, WOOL, MELON, EGG)` 共用**同一个**视界 `SN_H=48`。
应改成**每物品一个策略**：

| 类别 | 物品 | 做法 |
|---|---|---|
| 无人回收 + 平方曲线 | **MELON** | 抢在最早可行时点卖光（价格只会单向下跌） |
| 弱回收 + 平方曲线 | **WOOL** | 尽早卖（59 单位后就只剩 1 块） |
| 强回收 | **STRAWBERRY / MILK** | **不要抢卖**，跟着商店消耗节奏卖（等待有正收益） |
| 永不崩 | **WHEAT / EGG** | 无所谓，按计划卖 |

* 成本：改 `_OR2_SN_ITEMS` 为逐物品视界（一个 dict），机械改动、可回滚。
* 预期：把抢卖压力从"有回收"的品类移走，同时保住"无回收"品类的早卖优势。

### C2 订单槽经济学：不要把 10 个槽喂给 1 块钱的货

每步最多 10 条市场单。当某物品价格已被打到地板（=1）时继续挂单：
占槽、占甩卖排队，还会挤掉高价值物品的单。**做法**：价格为 1-2 时跳过该物品的卖单，
把槽留给高价品。改动极小、可离线直接验证。

### C3 商店消耗节奏对齐（微优化）

商店每 4 步消耗一次存货并**刷新价格**（价格在消耗后立刻抬升）。
把卖点对齐到"消耗 tick 之后的第一步"而不是之前，是纯免费收益。
需先确认引擎内 `_town_consume` 与撮合的先后顺序（读源码即可，已定位到 `_town_consume`）。

### C4 产出结构（高风险，最后做）

羊毛/西瓜/化肥的边际价早已触底，但仍占用格子与劳动。理论上把格子让给
小麦/草莓（永不崩 + 4 家店回收）更优。**但**历史证据是我们试过物种替换 −35k，
且产能面板显示双方结构完全相同 ⇒ 这条路风险高、且不解决"对手也一样"的问题。**暂不做。**
