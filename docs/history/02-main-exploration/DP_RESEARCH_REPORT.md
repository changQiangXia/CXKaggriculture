# DP 优化可行性研究报告（以 candidate_v50_npf4 为底）

时间：2026-09-20。目标：仔仔细细地尝试用动态规划（DP）优化 np_farm4
（`v50_np_farm4b.py`，SHA 8c692039…，即线上 ref 56384496 的源码）。

## 0. 方法与原则

DP 是单智能体最优控制工具。这个游戏是双方同时行动、共享市场的双人动态博弈，
整局做经典 DP 不可行（状态天文数字 + 对手耦合）。因此先把 DP 用在**对手行为
可预测**的子问题上，并用"完美信息 oracle 天花板"法验证：把对手的真实未来
动作注入 DP，测出机制的理论上限；若上限 ≤0，则任何在线近似都不可能赢。

两个被选中的真 DP 子问题（都有最优子结构）：

1. **终局清仓时序 DP**（672–719）：库存按商品独立演化，在"对手未来净成交
   已知"的假设下，我们的卖点是单边最优化，`V[t][c]` 带完整价格反馈。
2. **单回合订单排序 DP**（144–719）：引擎按 index 逐单位锁步结算，在对手
   订单流已知时，我们 10 张单的最优排列是精确组合优化。

## 1. 尝试一：终局清仓 DP —— 判负

构造：`v50_np_dp_oracle.py`（oracle 层）+ `dp_oracle_study.py`（对手净成交
重建 + 注入）。DP 含逐单位压价反馈、对手 719 终局抛售建模、卖完为止的硬终值、
同回合有买入时不砍卖单的守仓。

结果（fresh-62 全量，完美对手知识）：

- mean delta **−490.7**/局；仅 8/62 局改善、1 局翻胜，却有 **9 局把胜局打成
  负**（最惨 −3101）。
- 诊断：DP 把窗口内的卖出全部后置，与底盘的 terminal planner（712–718）/
  preguard/day-23 守仓/终局清仓互相冲突；简化价格模型在终局边界系统性高估。

结论：底盘的终局工程层已经优于"完美信息 + 简化模型"的 DP。判负。

## 2. 尝试二：单回合订单排序 DP —— 无空间

构造：`dp_order_ceiling.py`。用真实引擎的逐单位锁步模拟器，对每步把底盘当前
排序的收益与最优排列（卖单在前、买单在后，子集 DP 全枚举）比较。

重要过程：初版报告 mean +316/局，排查后发现是**零数量订单卡死模拟循环**的
测量 bug（把当前排序误评成 0）。修复后：

- 终局窗口（672–719）62 局：total +67，mean **+1.1**；
- 全游戏窗口（144–719）8 局抽查：+0 ~ +16，mean ≈ +3。

结论：`_adv_frontload`（卖单前置）+ `_r37_quote`（报价优先级排序）+ v44y
锁步 best-response 已经饱和了排序空间。无 DP 余量。

## 3. 其余 DP 角度（论证后不实施）

- **镜像抢卖 best-response DP**：lead 扫描已实证 lead12 打 V50 镜像 97.7%，
  残差是座位对称世界而非时序问题；且"改我方策略 = 同时改镜像对手策略"使
  best-response 定义失效。跳过。
- **生产路线 DP**：共享价格使单边 DP 的"外生价格"假设不成立；底盘 route tape
  本身就是手工调优的长程预计算（DP 的近亲），推倒重来风险极大。跳过。
- **商店 RNG 控制 DP**：leoprovorov 已证种子反推覆盖率仅 10–18% 且"控店≠赢"，
  DP 不解决信息层。跳过。

## 4. 总结论

对 candidate_v50_npf4，**经典 DP 没有可用的优化杠杆**。两个数学上良定义的
DP 子问题在完美信息 oracle 下分别测得 −491（有害）与 +1（无空间），说明底盘的
手工工程层（终局 planner、销售前置、报价排序、RACE 预约）已经占满了 DP 能
开采的结构。整局 DP 因对手耦合与维度灾难不可行；RL 此前也已判负。结论是
结构性的，不是实现粗糙。
