# 动物服务层（day22-29 喂食鲁棒化）设计 — 2026-09-23

## 目标
把原生羊群/牛群在"对手改变共享市场后"的断粮逃脱修掉。此前四次补丁（动物储备、
v233 双工、逃生守卫、取麦感知）已证伪，本层做的是**编排级修复**：当 tape 的
喂食编排被对手条件打散时，用一支专用工人小队按精英的节奏接管喂+护+取麦。

## 参照规格（从 Deodims / YumeNeko 真实回放逐命令提取）
- 精英 day27-28 仍维持 15-19 次 FEED + 15-25 次 CARE，两专用工人循环：
  PICKUP WHEAT 3 → 逐只 FEED → CARE → HARVEST → COLLECT_FERTILIZER →
  PLACE WOOL（送仓）。
- 我方 tape 本身 day27 就规划 17 喂/17 护、day28 9 喂；问题只在执行被打破。
- YumeNeko（7牛8鹅）精英 = 每天喂满 15/15 直到 day27；akmr（9牛3羊）同理。

## 触发（镜像零扰动是硬约束）
- day ≥ 22 且 8 ≤ hour ≤ 20；
- 存在任意动物 `consecutive_unfed >= 1` 且 `fed_today == false`（今日不喂就逃）；
- 触发后当日接管，喂完即退。镜像世界动物从不断粮两天 → 从不触发 → 字节不变。

## 机制（一次性多动物路线，不是逐只 ad hoc）
1. 选 2 名专用工人：优先 v233 的 SE 羊工；否则取"当前命令价值最低"的两个
   hand（PASS/COLLECT/纯移动优先，绝不劫持 HARVEST/PLANT/PLACE 送货）。
2. PICKUP WHEAT = 未喂动物数（一次拿够），shed 不足则先补一条 BUY_PRODUCT
   WHEAT（下回合可取）。
3. 对未喂动物做最短路径遍历，逐只 FEED；余力再 CARE。
4. 全程状态机：PICKUP→FEED_ROUTE→CARE_ROUTE→IDLE；动物被喂/季节结束即释放。

- 33+32 最新败局反事实；
