## 3. 机制解释

1. 门表主池（georgy 2400+、硬池 193、Top≥2900、AM 语料）全部是**冻结磁带**对手：
   arm 在打一个**不会反应**的对手。针对它优化的机制（抢卖窗口、预约提前、闲置收割）
   本质是"对固定 schedule 套利"，对手一旦会反应就失效。
2. 镜像/H2H 门的对手是**我们自己的血统**：在那里赢，等于在自家族谱上过拟合，
   与活体人群无关。
3. 天梯是**活体人群 + 按分匹配**：短窗/抢跑类机制在活体对手上反而损失稳健性，
   且低分段对手的打法与我们语料分布不同。
4. 结果：门表改进 → 线上退步；四天里我们的分数从 2676 一路掉到 2000–2540 区间。

## 4. 对本 goal 的含义

* goal 的 P0/P1 门（按定义）**不能作为"更强候选"的有效判据**：
  harmir/stack500 都按门表"通过"，线上却一致落后 m2，而 m2 又落后更早的 archplus。
* 因此本 goal 的"四线穷尽"应以**这份校准证据**结项，而不是以任一冻结磁带门表的通过结项。
* 唯一仍然可信的判据是：**线上分数轨迹**（同年龄对齐）以及**活体对手池**
  （双方均由源码驱动的对局，如 `panel_pool.py` 的 public/diverse 池，但需换成强对手）。

## 5. 建议（下一步方向，不在本 goal 内自动执行）

1. 停止按冻结磁带门表提交；后续提交前先用"同年龄线上轨迹"与活体对手池双重排序。
2. 把最强的活体对手装进评测：公开 notebook/仓库里的**源码**代理（不是它们的磁带），

3. 回溯 s1sd/archplus 那一代与当前候选的**活体 h2h**（双方都活），确认"老版本真的更强"
   还是"当年匹配池更容易"——这是唯一能把因果钉死的实验。

## 7. 结论（对"如何选候选"的可执行判据）
1. **冻结磁带门表**：与天梯负相关（§2–§3）——不可用作提交判据。
2. **天梯分数**：含明显的历史/年龄/匹配依赖（老候选活体弱 5k 仍高分）——只能作辅助。
3. **活体对打（双方都是活体 agent）**：目前唯一与我们手里证据自洽的强度判据，
   且必须用**血缘外**的对手（自家族 h2h 会被镜像护甲压制，测不出收割族差异）。
4. 已知活体证据：diverse/public 池（源码代理，双方活体）harmir +2,162/368 局领先 ch99；
   主血脉内 m2 > s1sd/snh48 ≥ archplus。
5. 待 harmir(16:54) / stack500(18:13) 干净读数；若两者仍落后 m2，则"收割族"按 §3 判定为
   **冻结磁带过拟合**，并把后续所有候选改为"血缘外活体对手 + 同年龄天梯轨迹"双门。

## 14. 可行的新评价协议（提案）
既然本地构造全部无效，唯一可靠信号必须来自天梯本身；同时 §8 证明跨日期比较无效
（同一份 archplus 老提交 2641 vs 重提 2495）。因此协议必须是**同日参照系**：

1. **每次提交批次固定带一个参照臂**（建议 s1sd，已知最强活体：vs2400+ 64.2%）。
2. 同批最多 4 个候选；6h 后用**同一时刻的同龄分差**（候选 − 参照）排序，
   消除"赛程变强/时点噪声"。
3. 候选的**入选依据不再是 G2/日包均分**，而是"与参照臂的机制差异要小、只改可解释的一处"，
   以便归因（因为我们已证明池内大增益与线上负相关）。
4. 本地电池仅保留两个用途：机制归因（消融）与"不出洋相"的底线检查（AM 胜局/AM107/镜像），
   **不再用它排序候选**。
5. 参照臂本身也要随赛程更新（例如每月/每周用当时最强的活体重设参照）。
