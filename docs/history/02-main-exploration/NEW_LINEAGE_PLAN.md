# 新血统计划：从零的协调式生产规划器（PLANNER）

**日期**：2026-09-29　**背景**：公开区/现有磁带血统的增量空间已穷尽（见 MECH_REGISTRY 第 1-11 批）；
唯一能改变量级的是"围绕作物排劳动"的规划器（=天梯顶端 3000+ 那一类）。

## 0. 诚实前提（历史证据）

* 40 个公开仓库的从零 agent 全部输给我们的磁带底座 4k-31k；2945 农场作者的从零 v10 线上只有 990-1578。
* DP 终局/订单排序：判负（完美信息 oracle 也 −490/局）。
* 硬杂合体（双底盘切换）：判不可行（状态机错位）。
* ⇒ **v0 的目标不是立刻打平磁带，而是"能完整跑、不崩、可迭代"**；里程碑拉到 3 段。

## 1. 架构（PLANNER-V0）

```
每回合 step:
  A. 市场模块（≤10 单）      B. 劳动模块（farmer + hands）
  1) SELL: 价≥地板 且 留饲料   1) 任务表：FEED/CARE/WATER/HARVEST/PLANT/
  2) BUY_SEED: 按当日计划            PICKUP/PLACE/BUILD/COLLECT_FERT
  3) BUY_ANIMAL: 有空栏 & 现金   2) 每工人：最近可达任务的价值×距离贪心
  4) BUY_LAND: 日阈值 & 现金     3) 站位即执行，否则朝目标走一步
  5) HIRE: 目标班组 & 现金
```

* **零磁带**：不读 routes/native，不使用任何 v9/ahmed 层。
* 复用仅限：引擎常量（`ANIMALS/CROPS` 语义）、走位/置换等纯工具函数（在新文件里自写）。

## 3. 关键设计点（吸收失败解剖）

1. **投资节奏**：前 10 天把现金滚进"地/动物/种子"，与磁带同型（我们的面板证明该节奏是对的）。
2. **劳动效率**：任务按"价值/距离"贪心，优先喂/护（FEED/CARE 占动物产出大头）。
3. **品类结构**：麦（饲料+走量）+ 胡萝卜（hinge）+ 草莓/西瓜（高价）+ 番茄（d16-20 补种，首收 d24+）。
4. **卖侧**：按品类地板价 + 留饲料；满 10 单时让位给高价品。
5. **可自适应**：所有阈值集中成 `PARAMS` 字典，便于后续扫描与状态门控。
