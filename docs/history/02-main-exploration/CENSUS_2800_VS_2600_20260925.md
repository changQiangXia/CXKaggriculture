# 本地 georgy 普查：2800+ 带 vs 2600–2700 带（零 API 成本）

工具：`georgy_census.py`（只读 episodes.csv 的 rating 列 + parquet 中匹配的 row group）。
样本：**HI ≥2800 共 250 局**、**CTRL 2600–2700 共 250 局**（从 09d/09e/09f 中随机抽，
候选池 2,323 / 8,294）。每局 720 步完整 replay（32 MB JSON），逐局解出目标玩家的动作与观测。

## 1. 结果（中位数；均值被重尾污染，见 §3）

| 特征 | HI ≥2800 | CTRL 2600–2700 | 判读 |
|---|---:|---:|---|
| 终局银行 | 98,186 | 98,831 | **无差** |
| 现金 d6 | 801 | 801 | 无差 |
| 现金 d12 | 14,487 | 14,068 | +3.0% |
| 现金 d18 | 39,932 | 38,710 | +3.2% |

| 请求卖出单位 | 85,691 | 85,707 | 无差 |

**结论：两个分数带在一切可靠可测的宏观结构上完全相同。**

## 2. 战略含义（本轮最重要的判断）

1. 天梯的胜负发生在 **±0.5% 的边际**上（~99k 银行上的几百块），不在宏观结构上
   —— 与我们自己的镜像测量完全一致（镜像差值 ±30…300，银行 ~100k）。
2. 因此**池子/普查型指标会系统性误导**：它们对宏观差异敏感，而天梯只对边际敏感。
   这解释了 candidate_final 的"池子 +566 ⇒ 线上 −98"与 SN_H 旋钮的 343 镜像点价值。
3. 候选必须继续在**微观时序**上迭代：订单簿置换预算、抢跑窗口、卖单排序、
   开盘洗单、末期递补 —— 也就是我们这一轮扫过的那批旋钮。

## 3. 方法陷阱（记录，避免重犯）

* 用**均值**看卖量会得出"HI 带少卖 3.7 倍"的假结论：分布是重尾——少数局挂出
  巨量**未成交**甩单（例如请求 1000 单位而市场只吃几个），把均值拉到 219,600。
  中位数 85,707 才是真实水平。任何"请求量"类指标都必须配成交/银行交叉校验。
* replay 里的 `SELL` 数量 = **请求量**，不是成交量；要成交量必须从
  市场库存 Δ + 城镇消耗反推，或从棚子轨迹推。
