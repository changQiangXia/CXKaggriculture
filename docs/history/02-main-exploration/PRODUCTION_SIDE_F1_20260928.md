# 生产侧单点实验 #1：施肥覆盖（F1）——判负（2026-09-28 11:20 UTC）

## 1. 引擎规则（已从提取语义中核实）

`_apply_unit_action` → WATER 分支（非持续作物）：
```python
age_days = day - tile["planted_day"]
window_start = (crop_data["max_yield_day"] + 1) // 2
if window_start <= age_days <= crop_data["max_yield_day"]:
    bonus = 2 if tile["fertilized_until_day"] >= day else 1      # ← 施肥让每次浇水翻倍
    tile["yield_units"] = min(crop_data["max_yield"], tile["yield_units"] + bonus)
```
FERTILIZE：消耗**单位背包里** 1 个化肥，`fertilized_until_day = max(..., day+2)`（覆盖 d/d+1/d+2）。

⇒ 小麦窗口 3 天（d+2..d+4）：不施肥 1+3=4 单位；**提前一次施肥 → 6（上限）**，+2 单位 ≈ +84 枚/田。
胡萝卜窗口 2 天：2 → 4，+2 单位。甜瓜窗口 7 天：上限 6。

## 4. 判读（重要教训）

1. **"PASS"不是闲置**：我方单位的 PASS 是计划中的**等待位**（等下一拍的取放/走位窗口），
   劫持它会连锁破坏后续物流——这与历史上"补动作/劳动重排"类实验（7+ 次全负）完全一致；
2. 施肥的净收益（+2 单位 ≈ 84 枚 − 1 个化肥的机会成本 ~50 枚 − 1 个动作的机会成本）
   在**劳动满负荷**的底盘上并不占优；
3. 覆盖率低 ≠ 浪费：R51 输入层是**影子模拟选优**（只在净收益为正时才施肥），
   20% 很可能是它算出来的最优覆盖，而不是漏洞。

## 5. 结论

* 生产侧单点实验 #1 **判负**（且是大负）；
* "提高施肥覆盖"这条路要成立，必须做**排程级重写**（先取化肥→提前走到田→在窗口前沿施肥），
  这已超出"单点"，且历史先例极差（劳动重排类全负）；
* 当前最强候选仍是 `cand_sn48_km_d27h0_rmax96.tar.gz`（全门全绿、未提交）。
