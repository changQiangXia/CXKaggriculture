**结论 1**：镜像不是随 SN_H 单调变化，而是**阶跃**——第二处赋值（8044 行，运行时全局）从 48 改成

**结论 2**：同一批种子上 (24,48)=−77 与 (24,24)=−218.5 的差距是真实的，不是种子组成造成的。

**结论 3**：直接头对头 —— **5b 输给 5a 242.7/局**（96 种子），**5b 输给 candidate_final 143.7/局**。
即在这条血统内部，SN_H=48 的版本是最强的，SN_H=8 的版本反而被压制。

### 读法（本轮核心结论）

1. **(48,48) ≡ (8,48) 逐位相同** ⇒ 4755 行的赋值是**死赋值**，生效的是 **8044 行**那个全局。
   之前所有"对称扫描"（12,12)…(40,40) 实际上都在改生效值，所以全塌。
2. **candidate_final 的 −289 全部来自 SN_H=8 这一个改动**。把 SN_H 回退（其余 5 个旋钮保留），
   立刻变成 **+54.4/局（t=3.63，53胜/19负）**——其余五个旋钮（CXD1600 / 开局洗单 / CAP16 /
   SLOT_MARGIN10 / CH_SHED97）合计是**镜像 +54 的正贡献**。
3. 已打包的 `candidate_snh8`(−319)、`snh8_combo`(−310) 同属"SN_H=8 ⇒ 镜像重伤"家族。
4. 用唯一线上锚点（candidate_final 镜像 −289 ↔ 线上 −98，斜率 ≈0.34 分/镜像点）：
   SN_H=8 的镜像代价 −289 对应线上 ≈ **−98 分**——与实际观测 2665.1 vs 2563.1 **吻合**。
   即：所谓"+536 强池收益"是**本地静态池的假象**，在天梯上完全没兑现。
5. 机制读法：SN_H 是"把未来计划卖单提前到本回合"的窗口。同血统对局是**价格战**，
   先卖者赢；提前 8 回合 = 卖得比对手晚 ⇒ 被压价。对外部弱池，提前卖反而是自己砸价，所以池子上显示 +536。
