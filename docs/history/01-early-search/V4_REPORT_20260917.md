## 本轮实际实现

### 1. 专属工人有限路线搜索

代码来自本轮冻结的 `worker/candidate_v45_q25_worker_v4.py` 末尾部分，并在 v3 上重新组合。它只处理已经确认的 V219 专属番茄工人，只改移动首步，不改立即要执行的种植、施肥、装货和收获命令。对现有 WATER→HARVEST 任务枚举最多 120 个、深度不超过 3 的前缀，再用父模型最近目标规则补全剩余路线；只有完整路线严格更短、任务没有丢失、当天能完成、首步确实不同并且搜索耗时在 8 ms 预算内时才接受。

真实对局中该分支的 telemetry 显示它确实运行了搜索，但 `worker_search_accepts=0`、`worker_search_changed=0`，也没有错误。此前独立机制检查的 24 个实际对局同样是零动作变化；这说明当前真实专属路线已经很紧，不能把合成几何案例里的缩短路线直接当作强度收益。

### 2. 可执行的空闲动物收获搜索

dry-run 版本发现“整天禁止未来 HIRE”会把所有真实机会拒绝掉，所以 v4 改成了更窄的执行状态机：

- 只在当前父动作是 `PASS`、工人不是专属工人或 pending 工人、手上没有货物时考虑。
- 只看当前信息和父 tape 的未来动作；要求接下来至少 3 个 PASS，最长只占用 8 个 callback。
- 只选择一个已经有产出的 COW/SHEEP/GOOSE，且完整路径是“走过去 → HARVEST → 回到原来的格子”。
- detour 内不允许 HIRE、FEED、PICKUP、PLACE、DROP、CARE 或 COLLECT_FERTILIZER；父模型以后可以在原位继续工作。
- 用 BFS 避开 WEED，检查仓库和各工人携带物总量不会超过 100；不依赖最后一天自动回仓。
- 下一 callback 检查位置、父动作仍为 PASS，并检查 HARVEST 后货物数量确实增加；发现偏离就停止该 detour 并记录 abort/recovery telemetry。
- 通过 `globals().pop('agent')` 保证 Kaggle 的 `get_last_callable` 取到真正的 agent，而不是最后定义的辅助函数。

官方 `_apply_unit_action` 内核上的合成测试在 200..204 callback 执行了 `EAST → HARVEST → WEST`，确认收获 1 单位 MILK、回到原点、确认收获和完成状态各计数一次，错误数为 0。测试文件是：[test_idle_active.py](/root/autodl-tmp/q25_search_20260917_055120UTC/worker/test_idle_active.py)。

## 真实验证

主验证结果在：[v4_joint_final_9065_9067.json](/root/autodl-tmp/q25_search_20260917_055120UTC/worker/v4_joint_final_9065_9067.json)。它使用完整 720 callback 的官方 `kaggriculture` 环境、同一初始 seed、双方 seat 对调的 paired evaluation：

| 对手族 | seed | 配对行数 | 健康行 | v4 与父模型结果 | 现金差 | 动作变化 |
|---|---:|---:|---:|---|---:|---:|
| v37 | 9065, 9067 | 4 | 4 | W→W 全部 | 0 | 0 |
| nathan | 9065, 9067 | 4 | 4 | W→W 全部 | 0 | 0 |
| thomas | 9065, 9067 | 4 | 4 | W→W 全部 | 0 | 0 |
| **合计** | 4 seeds | **12** | **12** | **W→W 12 行** | **0** | **0** |

所有行都是 `DONE`，无 `ERROR/TIMEOUT/INVALID`，无 stderr；配对评估 `ok=true`。这里的 `actual_candidate_wins=12` 和 `actual_parent_wins=12` 只是双方在各自对手局中的相同胜负结果，不能说 v4 赢了父模型。

空闲 overlay 的真实 telemetry 解释了为什么没有动作变化：

- 9065/9067 的每个 seat 都发现了若干 PASS 窗口，但正收益动物目标大多已经被父模型后续 HARVEST 预约，剩余目标的往返路线长度超过当前 PASS 窗口。
- 例如最终面板中 `idle_active_windows` 约为 11–17，`idle_active_positive_animals` 约为 13–15，`idle_active_reserved_targets` 约为 10–13，而 `idle_active_proposals=0`；错误、abort、recovery 都为 0。
- 这不是代码异常，而是当前“必须回原位并当场接回父路线”的安全约束没有暴露可执行机会。放宽为直接打断后续任务会改变工人职责和未来市场数量，当前证据不足以支持这种放宽。

此外在 9068/9069 的 v37 开发检查中，候选仍为健康的 W→W，动作变化为 0；这些 seed 只作为开发诊断，不能当作未见 holdout。

压缩包又用 evaluator 重新加载做了 9065 双 seat archive smoke test；两行健康，源码和 archive hash 与上面的冻结值一致。结果在：[v4_archive_smoke.json](/root/autodl-tmp/q25_search_20260917_055120UTC/worker/v4_archive_smoke.json)。

## 审查和限制

1. 专属路线搜索的“228 个合成案例更短”只证明几何搜索机制，不证明真实胜率；真实 24 局没有改动作。
2. 空闲 overlay 只在合成官方内核场景实际执行过；真实配对中没有触发，因此没有真实收益或风险样本。
3. 当前配对种子 9065/9067 属于已有开发集合，不能当成全新确认集合；由于候选在真实对局中没有改变动作，继续在更多相同路线族 seed 上重复不会自动产生强度证据。
4. 没有运行 fresh confirmation seeds，也没有提交。这是有意的：晋级门槛要求有非零动作、物理任务完成、全健康，并在多对手族上看见稳定的正向差异；v4 当前不满足“非零动作/已观察收益”这一前提。
5. 如果要继续研究，下一步应先从新 tape 或新对手中找出实际存在的“短 PASS 窗口 + 邻近未预约动物”，或者设计能严格预测父模型任务延迟的全局调度器；不能仅靠放宽当前门控来制造动作变化。

本轮没有执行 Kaggle 上传。
