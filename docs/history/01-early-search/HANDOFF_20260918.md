## 源码审计结论

详细审计：`v3_online_analysis/SOURCE_AUDIT_CANDIDATE_V45_20260918.md`。

### 订单层

当前源码有多层会改变订单：

- `_v224_sales_first`（约 1478–1494）会移动 SELL；
- `_r36_reserve`、`_r37_reorder_sales` 会维护销售债务和 SELL 块；
- R97/R128/R148（约 2743–3329）可能新增或调整 WHEAT、seed、overflow 订单；
- 最后还有 R149/R150、RACE、OPEN 等层。

因此任何新 order-only 实验必须：

1. 先调用完整父动作；
2. 深拷贝 market list；
3. 只做有边界的排列，不改变任何 operation/item/quantity；
4. 不跨 `HIRE`、`BUY_LAND` 或同商品 BUY barrier；
5. 任何异常或安全检查失败都返回父动作；
6. 使用最终的 `agent=globals().pop('agent')` 导出保护。

安全插入点是完整父链之后，当前最终 OPEN wrapper 的导出保护之后，约源码第 3496 行。这样新层观察到 R128、R148、R149、R150、RACE、OPEN 的最终动作，并避免后续层重新改写其输出。

### worker 层

- `_v219_worker` 约 1387 行按 Manhattan 距离选择最近任务；
- `_v233_worker` 约 2025–2027 行同样按最近任务选择；
- `_r51_input_path` 约 2167–2196 行已经有 width 8、depth 8 的有限 beam，但只针对有限输入路径；
- `_r53_labor_assignment` 约 2347–2374 行只在 day 26–28、前两小时做小规模 worker group permutation。

第一轮不要原地替换 `_v219_worker` 或 `_v233_worker`，因为它们与 pending hire、fertilizer loading、harvest credit、next-callback confirmation 状态机耦合。若订单层先通过，再只测试一个 actor、一个很短 suffix；有 R128 service swap 或 R148 overflow pending 时直接回退父动作；要求零新增 overflow，并且每个 actor 的 deposit 不低于父动作。

终局 planner（约 712–718 步）只支持 terminal route，不能拿来做中局通用 market/order planner。

### 2. 完善官方内核订单 oracle

优先修改 `market_order_oracle.py`，为每行记录 `episode`、callback、day/hour、market inventory、cash、订单数量和成交数量摘要。然后对现有全部可用 replay 做分层统计：

- `BUY_SEED → BUY_PRODUCT`；
- `SELL → BUY_PRODUCT`；
- `SELL → BUY_ANIMAL`；
- `SELL → HIRE`；
- 混合订单和超过 6 个订单的受限排列；
- 阶段、市场库存、现金余量、订单数量、胜负和 seat。

保持“描述性单回合 oracle”边界，不把局部收益求和当作整局收益。对每个排列应优先记录实际成交量和失败原因，而不是只看请求数量。

### 3. 构造最小安全的 order-only 候选

只有统计确认模式跨多个 episode/对手重复出现后才开始。候选必须放在完整父链之后，默认只允许：

- 父订单的去重排列；
- 相邻交换或单订单跨有限槽位移动；
- 不改变数量、不删订单、不新增 HIRE/BUY/SEED；
- 不跨 HIRE、BUY_LAND、同商品 BUY barrier；
- 发生异常、订单数超限、资金/容量安全检查失败时原样返回父动作。

不要在候选里嵌入第二套市场模拟器。离线 oracle 与真实 engine 必须是同一官方语义。

### 4. 用反应式对手面板验证

使用至少 8 个新 seed、双 seat，覆盖：V46、Reactive7、Pipe8，以及一个异构 Thomas/Dmitri 家族。完成 720 steps、DONE、零 stderr/timeout 后，比较 parent/candidate 的 point、W/T/L、margin、产量、overflow、seat 方差和运行时间。只有 point/WLT/margin 没有尾部退化，且订单层行为确实改善，才考虑路线层。

### 5. 再考虑 worker 短窗口规划

订单层通过后，先做一个 actor、短 suffix、严格父动作回退的实验。候选任务只允许“继续父路线 / 完成一个高价值任务后回仓 / 修复一个即将过期任务”等少数方案；通过官方单位内核检查成熟、输入、回仓、容量和交付。不能一次替换全部 worker 的最近任务贪心。
