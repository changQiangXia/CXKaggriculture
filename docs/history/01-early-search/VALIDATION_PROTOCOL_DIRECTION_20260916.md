# 从本地实验判断线上方向的严格协议（2026-09-16）

这份协议用于 V37/V43、Nathan corrected、competitive V45 及其微调候选。目标不是证明本地分数等于 Kaggle 分数，而是在模型冻结以后，用未见过的对手族和随机世界，尽量可靠地判断改动的方向，并拒绝只对一组录像或路线有效的补丁。

## 1. 先冻结对象，防止信息泄漏

每个候选必须记录父源码和引擎 SHA、tar SHA、创建时间、改动开关、设计时使用过的 seed/回放/对手。源码冻结后才产生 holdout 结果；任何看过 holdout 结果的候选都不能再次作为 holdout 报告。

对手按策略族而不是文件名分层：

* V37/V43 同一路线族；
* competitive V45 的 shared-market opening/clone race 族；
* Nathan 的 sales-first/固定 route 族；
* flex、Thomas、Dmitrii 等动态或不同架构族；
* 最后一组是冻结后才选取的近期公开模型或新生成的随机策略，作为时间外样本。

同一作者的 v37、v43 不能算两个独立族；同一 notebook 的包装变体也不能增加有效样本量。

随机世界按时间和用途分开。开发 seed 只能调参，验证 seed 只能挑选候选，最终 holdout seed 在候选冻结后才揭示。每个族至少 12 个 seed、两个 seat；资源允许时用 16–24 个 seed。另加一组未见的随机 seed（例如由固定 hash 生成，提前只记录 hash 而不看结果）。过去反复使用 9001/9004 的实验只能作为历史诊断，不能充当新的 holdout。

## 2. 配对运行方式

对每个 `(候选, 父版本, 对手族成员, seed, seat)` 运行完整 720 callback。候选和父版本使用相同的初始 seed、相同对手、相同 seat；两者都从干净进程加载。可交换运行顺序以排除 CPU/runner 影响，并对一次重复运行检查引擎确定性。

这是 common-initial-world 配对，而不是重放父版本的动作 tape。候选一旦改变动作，后续价格、town 消耗、生产和 RNG 自然分叉；固定 tape 替换不能用于收益估计。

每场都必须确认 `DONE`、720 steps、无 stderr/超时，并保存逐场 JSON。任何异常场不能静默丢弃，应计入失败率并停止晋级。

## 3. 必须保存的指标

最终指标以候选相对父版本的 paired delta 为主：

* 自身 final reward、对手 reward、margin（自身减对手）；
* 每个策略族的均值、中位数、胜/负/平、10% 分位数和最差三场；
* 以 seed 为聚类单位的 bootstrap 95% CI，不能把同族两个 seat 当作独立世界后直接给普通标准误；
* 首次动作差异 callback、实际触发次数及触发前后的状态快照；
* 实际成交量和成交收入（SELL 请求量单独记录），BUY/HIRE/LAND/ANIMAL/SEED/FERT 成本，town 服务、产量和 shed overflow；
* 完成率、异常率、最大 callback 延迟。

对共享市场改动（例如 V45 step-0 round trip）必须额外按对手 opening 分层：第二槽 BUY wheat、先 SELL 再 BUY、无 wheat round trip。报告每类的成交价格、seed 是否少买、随后 shop/产量变化；不能只报告总 margin。

## 4. 两阶段验收门槛

### Pilot（验证集）

先跑每族 8 seed × 2 seat。若候选在所有非目标族的平均 paired delta 小于 -100 币、出现任一小于 -2,000 币的灾难局、或有任何异常/加载失败，立即淘汰。Pilot 只决定是否值得付出完整面板成本，不能据此提交。

### Confirm（未见 holdout）

候选冻结后跑每族 16–24 seed × 2 seat，至少四个策略族和一组时间外模型。晋级至少同时满足：

1. 按策略族等权的平均 paired delta > +150 币，且按 seed 聚类 bootstrap 的 95% CI 下界 > 0；
2. 至少 3/4 个主要族的族均值不低于 -50 币，任何族的 CI 下界不低于 -300 币；
3. 总体 10% 分位数不低于 -1,000 币，最差局不低于 -2,000 币；
4. 胜率相对父版本下降不超过 5 个百分点，完成率为 100%，无新增运行错误；
5. 激活日志显示收益不是由单一 seed、单一 callback 或少于 5% 的偶发触发构成。

若改动明确只针对某族，必须把该族单独标为 exploit；只有在其他族不出现实质退化时才允许进入通用候选。任何不满足第 2 条的候选都不能因为总体均值为正而晋级。

## 5. 机制和消融验证

每个改动先实现 telemetry，再做完整策略测试。日志需要记录候选是否真的改变了 action、订单 index 是否移动、请求量与实际成交量的差别，以及 24/72 步后的现金和库存变化。零 delta 不能被解释成“没有触发”，必须查看 action hash 和触发计数。

机制消融必须在相同 seed/对手/seat 的独立完整对局中进行：父版本、只关闭该开关、只保留该开关的最小版本。局部反事实或固定录像只用于定位机制，不用于估计线上分数。对于会改变 RNG 的 step-0 或生产动作，不能声称简单 cash fork 是因果收益。

## 6. 多候选和线上校准

一次研究可产生多个候选时，开发集允许自由探索，但 Confirm holdout 只对事先登记的最终候选运行；不得看到结果后在同一 holdout 上反复修改。可用简单的 alpha-spending：先 pilot，只有通过才跑 confirm；确认阶段最多登记两个候选，报告两者全部结果。

线上分数受提交时间和对手池影响，不能把不同时间的绝对分数直接和本地 margin 对齐。只记录“本地协议预测的方向”和提交时间附近的线上相对变化；若出现相反方向，优先检查对手分布、随机世界和共享市场耦合，不能事后挑选有利的局解释。

按此协议，当前 V45 step-0 exploit 只能作为 opening 分层的条件策略；V43 h4→h8 已因跨族平均为负被淘汰；Nathan corrected 目前只有 loader 一致性证据，必须先建立 sales-first 账本再进入候选确认。
