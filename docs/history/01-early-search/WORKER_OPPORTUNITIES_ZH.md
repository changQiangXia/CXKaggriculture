# Q25 / V3 工人层独立审查（2026-09-17）

审查对象是冻结 Q25 的工人层以及已有线上回放；V3 只附加市场层，工人主干相同。此文只确定可泛化机制与风险，不把固定回放反事实结果当作强度证据。

## 结论

最值得单独试验的是“空闲窗口内取走已产出的动物产品，并在下一项原任务开始前回到原位”。不应先大改全场路线。原模型多数工作来自事先生成的动作 tape，并非每回合都“最近作物优先”；贪心主要出现在番茄/额外羊工人叠层。输入肥料工人已经包含 beam search，末期番茄工人也有分组排列搜索。

真正无效的非 PASS 动作很少。六场近期 Q25 loss 的 41,374 个真实存在单位动作中，2,934 个是 PASS，只有 256 个其他动作被官方单位规则判定为无状态改变（约 0.62%）。因此不支持“工人大量出错造成当前线上失分”的强断言。原地收货机会确实存在，但一般移动后再接回的机会不多。

## 可复核证据

`audit_replay_workers.py` 使用 `steps[t]` 的动作前状态和 `steps[t+1].action`，按官方 `_apply_unit_action` 的单位顺序执行，包含全体同作物 PLANT 原子拒绝；使用 seat 0 共享农场与己方 private，seat 1 缺省 step 时用回放下标。每场 690 个非日终 callback 的主农夫及既有帮工终点位置均与原录像一致。总计 4,140 次位置核对通过。

这不是全局状态重演，也不是新策略收益预测。只用原录像未来动作排除“本来同一天其他单位会收走”的目标，runtime 不得访问未来录像。

窗口表包含原地 HARVEST / COLLECT_FERTILIZER，也允许经官方验证无效的非 PASS 动作；因此它是宽松机会筛选上界，严格只替换父模型 PASS 的 v4 触发会更少。同目标的重叠窗口不能相加估计利润。

具体可研究的原位接回实例：

- 109873587，callback 333 和 405，主农夫在 `[7,4]` 有三回合空闲，可到 `[6,4]` 收取 4 个动物产品，再回原位。
- 109881960，callback 605，actor 3 从 `[6,3]` 到 `[6,2]` 收取 3 个动物产品，三步内回到原位。
- 109864978，callback 627，actor 9 在 `[5,4]` 有三回合空闲，可选择原地收 3 个产品，或走到 `[5,3]` 收 2 个后回原位。选择需要真实当前产品价格，最近目标不足以确定价值。
- 多场在 callback 628/629 的仓库入口 `[5,4]` 尚有 3 个动物产品，原地操作即可获得；这类机会适合先隔离测试。

109873587 最后一天还有许多粪肥窗口，原始宽松结果共有 55 个窗口，但尚无货物送仓和订单兑现证明，主表已排除它们。不能把最后时刻背包里的货物计为现金。

回放中的真实非 PASS noop 以 CARE、COLLECT_FERTILIZER、WATER 为主，通常已经由别的单位完成，或对应地块生产未成立。比如 callback 91 的 CARE 位于已经 cared_today 的奶牛上；callback 107/111 的 COLLECT_FERTILIZER 指向已无肥料的羊。某些 noops 有保守同步作用，不能单看计数就替换。

## 适合 v4 的隔离边界

建议先只考虑正常生产期的主农夫和 native 帮工，当前父动作必须 PASS，携带物为空；不借用番茄、羊、输入肥料叠层拥有的 actor，也不借用有 pending 修补动作的 actor。候选目标限制为已产出的 MILK、WOOL、EGG，未来自有 tape 同一天不再指派任何单位收该目标。

对 1 个或 2 个目标的路线做有限枚举，完整计算出发、收获、回原位所需步数，必须放得进 <=8 步连续自有 tape PASS 窗口。带上原动作/不行动候选。评分可以比较当前库存价格下的边际产品价值与用时，当前价格只是排序启发，不能当作未来成交保证。

只有最多一个 actor 处于 excursion；每一步核对真实位置、父动作仍为 PASS、目标仍存在、剩余距离能接回。新货物必须有本日原路线送仓 DROP 或非终局的日终自动入仓出口。当前 `shed + 所有单位 cargo + 新货物 <= 100` 是必要检查，不能保证未来数回合不被其他产出/购买填满。

尚不能静态保证所有上层响应式逻辑在被移动后的状态下仍返回 PASS。尤其 `_r128_service` 会在仓库入口把 PASS 改为取麦，`_weed_repair` 会将 PASS 改成 DIG；父状态中 pending 可能被位置改变清空。遇到父动作打断再返回原位有可能错过新的真实任务，因此不应把“能够回去”称为无损保证。先做 dry-run proposal 与触发证据是合理的停靠点，再单独审计后开放实动作。

## 危险交互

- 动物 HARVEST 不删除地块，相比提前收获普通作物，不会直接改变空地杂草抽样数量；但额外现金及后续父模型响应仍可影响以后的 RNG 和发展路线。
- 肥料有真实投入用途。额外 COLLECT_FERTILIZER 会让后面本来缺料的 FERTILIZE 生效，不能按“仅多一份可卖货物”处理，因此首个原型排除它。
- 多个单位按下标顺序取货、放货与收获。候选需要全局目标预约；否则两名工人可能追同一份资源。
- 新货物可能让 DROP 或日终自动入仓挤出父模型更高价值产品；`_R148_PENDING` 还要求精确的次回合库存。
- 主农夫/帮工搬动可能改变 HIRE 的入口分配，改变后来所有 actor 对应路线；有计划内或响应式 HIRE 的 excursion 需要禁止或精确模拟。
- 父模型 `_RACE_STATE[player]['prev_action']` 要和最终执行动作一致。只修改外层动作而不维护它会影响竞争检测。
- 原始路线不等于完整父动作；杂草修补、terminal shadow、番茄/羊/肥料工人、service 预取等都会覆盖。不得把 raw tape 当作对完整父模型的精确预测。
- 日终所有帮工离场并自动入仓，主农夫回仓库。最终 callback 为 718，不能假设会执行第 719 个 callback 的完整一天收尾。

## 验证指标

先做官方单位差分/路径合法性与“不抢既有收货”测试，然后测 proposal 触发率和父动作打断率。真正执行版本需报告开始/完成/回原位次数、最坏接回延迟、父任务被覆盖数、确认收货量、入仓量、真实新增售出量、废弃货物、pending 异常、HIRE 入口变化、p95/max callback 耗时。

强度验证仍需完整可响应对手，双方座位，冻结父 Q25 与 V3 对照，分 worker-only / market-only / joint。以终局 W/T/L 和胜负转换为主，现金 margin、关键生产时间、最差对手家族与搜索触发率为解释指标。不能用这里的回放窗口数量估计线上会提升多少分。
