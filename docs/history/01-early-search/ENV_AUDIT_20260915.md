# 本机本地验证环境审计（2026-09-15）

- Host CPU reports 128 logical CPUs (Xeon Platinum 8352V), but cgroup `cpu.max=50000 100000`, so this container is limited to 0.5 CPU. `nproc` returns 1.
- cgroup CPU pressure shows sustained throttling (`nr_throttled=86481`, `throttled_usec=23380813853`).
- cgroup memory limit is 2 GiB (`memory.max=2147483648`), despite host `free` showing ~1 TiB. At audit time `memory.current` was ~1.65 GiB; most usage is file cache from large replay/code files. No OOM kill yet, but deep-copy-heavy debug runs approach this limit.
- No GPU is exposed (`nvidia-smi: No devices were found`). GPU is irrelevant for the Kaggriculture rule engine, which is CPU-bound.
- `/root/miniconda3/bin/python` provides `kaggle_environments` package metadata 1.25.9. The installed Kaggriculture interpreter was previously shown behaviorally parity-compatible with online module 1.32.7 on four replay audits (`experiments/h5_engine_audit/ENGINE_PARITY_REPORT.md`), so package metadata alone is not the current timeout cause.

Recommended runner: pinned `/root/miniconda3/bin/python`, `debug=False`, one worker (at most two only after memory test), staged seeds, and a per-game subprocess timeout. Avoid the old serial `debug=True` runner for panels.
