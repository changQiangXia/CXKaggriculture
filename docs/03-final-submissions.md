## 1. 槽 A：`cand_comb2b.tar.gz`

**Kaggle ref** `56718170` · **sha256** `7ae295923b95ecbc746eee5ab4f983fde8a2050f9225b338194bf2a61fdc8908`

### 1.1 血统

```
w2_120  ──[去掉 V92_P + V9_RACE 两层]──▶  comb  ──[改 3 个常量]──▶  comb2b
```

`w2_120` 是路线三段拼接（d12–19 用路线 104、d20–26 用路线 120）的磁带 agent。
`comb` 在它之上关掉了两个"抢先卖 / 预测对手卖单"的市场层。
`comb2b` 再改三个常量：

```diff
- _R37_PRICE_FLOOR = 1          + _R37_PRICE_FLOOR = 2
- _R37_HINGE_GAIN = 8.0         + _R37_HINGE_GAIN = 6.0
- V9_FERT_FIRST_DAY = 14        + V9_FERT_FIRST_DAY = 12
```

相对父本 `comb` 共 **6 行 diff**（3 处删除 + 3 处添加）。

### 1.2 每一处改动的证据

**`V9_FERT_FIRST_DAY 14 → 12`（主力）**

| 对手池 | 局数 | Δmargin/局 | t |
|---|---|---|---|
| 108 局冻结面板 | 108 | **+84** | 5.10 |
| 131 局真实对手池 | 131 | **+82** | 4.67 |
| 76 局独立对手池 | 76 | **+94** | 2.47 |

阈值扫描（108 面板）：

| 首施日 | 胜/负 | 平均 margin |
|---|---|---|
| 8 / 10 / 11 | 61/47 | +99 |
| **12 / 13** | **63/45** | **+117** |
| 14（原值） | 64/44 | +33 |
| 16 | 65/43 | +24 |

12 与 13 在该面板上**逐局完全相同**（delta = 0.00），行为上呈窗口开关；
14 恰好落在窗口外。“提前启动水肥循环”是机制假设，而非单独隔离的因果证明。

**`_R37_PRICE_FLOOR 1 → 2`**：留一法显示去掉它 −27/局（t=−2.26），是第二承重项。

**`_R37_HINGE_GAIN 8.0 → 6.0`**：单独影响 +1/局，无害。

三者叠加的三池结果：

| 池 | Δmargin | t |
|---|---|---|
| 108 面板 | **+112** | 5.55 |
| 131 局对手池 | **+108** | 5.38 |
| 76 局独立池 | **+113** | 2.80 |

### 1.4 已知局限

* 与 `comb` 在统计上**不可区分**（去掉单局离群后 varA−comb 由 +64 变 −27，
  t=−0.88）。真正的贡献来自"去掉 V92_P"这一步，而不是加回 V9_RACE。
* 在**冻结回放**评估里它优于 `w2_120`（+238/局，t=13.5），但在**直接对打**里
  反而输给 `w2_120`（67–80%）。见 `04-lessons.md`。

## 2. 槽 B：`cand_w2_120.tar.gz`

**Kaggle ref** `56716540` · **sha256** `efb63eb6efd6d5155547ffb14ccd55421d1a661d8398d9182b8309bbc95177eb`

### 2.1 这是什么

**与 ref `56697965` 完全相同的文件。** 那份在 09-30 05:13 提交，
public 曾达到 **2203.1**（我们整场比赛的最高读数）。

19:06 重发同一文件的动机：当时追踪槽是
`[w2_120 (2203.1), comb_pp_race (1943.9)]`，而 `comb_pp_race` 已停滞。
重发的意图是"用一个已知 2203 的产物顶掉 1943 的弱槽"。

**实际效果：** 新提交从基线 600 起步，到截止时只爬到 2072.3
（旧槽的 2203.1 已随旧提交被移出追踪）。

### 2.2 血统

```
（cam30 基座）──[d12-19 路线 104 / d20-26 路线 120]──▶  w2_120
```

历史验证：7 个池共 1,342 局，净 +43 翻转；最新 live meta 上 +10/58；
低分段零退化。

### 2.3 关键教训

**同一份代码两次提交，读数差 131 分（2203.1 → 2072.3）。**

原因有二：(a) 新提交从基线起步，需要数小时到一天才能爬到真实水平；
(b) 场上环境变了——同一份代码在不同时段的天梯分不可比。

这直接导致我们后来在 `04-lessons.md` 里写下的一条规则：
**"比较两个提交的分数，必须限定在同一时间窗内"**。
