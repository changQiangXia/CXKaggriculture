# 06 · 我们的方案：路线回放器、路由器与反应层

本文回答一个比“用了什么模型”更具体的问题：**终局提交里的 `main.py`
究竟怎样把一个观测变成一个动作，为什么它能在 10,148 支队伍中进入前
5.02%，又为什么最终停在银牌线下 1 分。**

这是一份**事后重建**：代码结构与常量以终局 `main.py` 为准，实验动机与
结论来自当时日志；两者不能互相替代。

结论先说清楚：这不是一个从零训练出的神经网络。它是一台
**按商店条件选择路线的动作回放器**，内置 41 条完整路线，每条路线包含
719 个可执行回合（step 0–718，覆盖 720 步的 episode）；路线之外再叠加
约 60 个包装/控制点，负责开局、施肥、羊群、劳动、市场卖单和异常兜底。
“层”的数量是一个源码统计口径，不代表有 60 个独立模型同时做决策。

更详细的比赛时间线见 [`01-timeline.md`](01-timeline.md)，逐项实验结果见
[`02-experiments.md`](02-experiments.md)，提交与常数证据见
[`03-final-submissions.md`](03-final-submissions.md)。本文主要解释方案本身。
证据等级与口径定义见 [`08-evidence-and-scope.md`](08-evidence-and-scope.md)。

## 1. 一张图看懂执行路径

```text
Kaggle observation
        |
        v
外层包装链（市场重排、终局清货、价格门、兜底等）
        |
        v
Chassis（路线回放底盘）
  |-- Router：根据商店、对手开局和三个时间边界选择路线
  |-- Tape：取出该路线在本 step 的 farmer / hands / market 动作
  |-- Base reactive layers：对齐工人、修杂草、提前卖、棚屋保护等
        |
        v
字典动作 {"farmer": ..., "hands": ..., "market": ...}
        |
        v
Kaggle engine
```

包装层不是预处理流水线：它们大多先调用内层得到动作，再对返回的字典做
改写。因此同一张图也可以读成“Chassis 在中心，包装层由内向外套住它”。

源码中的 `Chassis.act()` 有一段关键的故障隔离：如果某个反应层抛出异常，
底盘返回**未经改写的原始磁带动作**；如果整个入口都无法构造动作，才退化为
`PASS`。这能避免代码异常直接中断决策，但不保证该层在无异常时一定有益。

## 2. 方案对象：41 条路线，不是一条固定脚本

解包 `candidates/cand_comb2b.tar.gz` 后，可以对静态对象作如下核对：

| 项目 | 终局值 | 含义 |
|---|---:|---|
| 路线数 | 41 | 每条路线都是完整的 719 步动作序列 |
| 每路线可执行 step | 719 | step 0–718 |
| 新商店映射 | 64 行 | 前两个解锁商店 → 路线 |
| 旧商店映射 | 64 行 | 羊毛专精世界的专家路由 |
| V92 覆盖表 | 15 行 | 含 `YARN_STORE` 的商店组合覆盖 |
| 对手例外表 | 1 行 | 一个开局资金/库存特征专属路线 |
| 终局包解压大小 | 约 1.06 MB | 单文件、标准库、自包含 |

每条路线的动作格式是：

```python
{
    "farmer": ["WATER"],             # 农夫动作
    "hands": [["MOVE", ...], ...],    # 每个工人的动作
    "market": [["SELL", "WHEAT", 8]], # 最多 10 个市场槽位
}
```

磁带同时编码了生产、劳动和市场节奏。它不是把“农场状态”作为输入后逐格预测，
而是把一条经过筛选的完整轨迹冻结下来，只在明确可计算的条件下做局部改写。

### 为什么路线重要

在 Kaggriculture 中，农场的建造、取放、喂养、照料、收获和卖单共享同一个
劳动预算与现金流。只改一个动作往往会让后面的动作相位错位。我们用“整条路线”
作为最小实验单位，正是为了保留这条因果链，避免把局部最优误当成全局最优。

历史审计曾把 41 条路线逐字节比较：作物配比大体同构，但开局和不同世界下的
路线选择不同。第 6 天的商店解锁是公开状态，因此它成为最自然的路线选择信号。

## 3. Router：终局候选的实际路由逻辑

终局 `comb2b` 的 Router 没有使用神经网络，也没有在线学习。它只读取公开
状态，做一个确定性的分段决策。下面是按源码整理的伪代码：

```python
def router(observation, step, state):
    if step == 2:
        rival = observation["farms"][1 - observation["player"]]
        state["rkey"] = (
            round(rival["money"], 3),
            observation["market"]["inventory"]["WHEAT"],
        )

    if step >= 144 and not state.get("day6"):
        shops = tuple(observation["town"]["unlocked_shops"][:2])

        if "YARN_STORE" not in shops:
            route = NEW_SHOP_TABLE.get(shops, 100)   # EXP240
        else:
            route = OLD_SHOP_TABLE.get(shops, 0)     # V39

        route = V92_TABLE.get(shops, route)

        if "YARN_STORE" in shops and state["rkey"] in RIVAL_EXCEPTIONS:
            route = RIVAL_EXCEPTIONS[state["rkey"]]

        state["route"] = route
        state["day6"] = True

    if 288 <= step < 480:       # day 12–19
        route = 104
    elif 480 <= step < 648:     # day 20–26
        route = 120

    if step >= 648:             # day 27–29
        route = 2

    return state.get("route", 0)
```

把三个时间边界写成人类可读的形式：

| step 范围 | day | 路线行为 |
|---|---:|---|
| 0–143 | 0–5 | 先用统一开局路线；第 6 天前按默认路线运行 |
| 144–287 | 6–11 | 读取前两个解锁商店，按 64 行表选择世界专属路线 |
| 288–479 | 12–19 | 固定使用路线 104 |
| 480–647 | 20–26 | 固定使用路线 120 |
| 648–718 | 27–29 | 切到路线 2，进入末期 |

`w2_120` 这个名字就来自这里：**第二个中后段窗口使用路线 120**；
同一段拼接的前一个窗口使用路线 104。`comb2b` 保留了这套路由和两段
104/120 的拼接，只在外层关掉两个市场层并修改三个常量。

### Router 为什么不继续复杂化

我们对 day-6 表做过留一法重拟合、对路线边界做过 27 组合联合扫描、对
开局窗口做过 12 个固定替换。表内拟合可以变好，但留出局没有稳定收益；
边界替代和路线替代也全部下降或与现役打平。因此终局没有增加一个“更聪明的
分类器”，而是把已经能泛化的公开状态路由保留下来。

## 4. Chassis 的九个内置开关

`Chassis` 自带九个可开关的反应能力。终局包的初始设置并不是全部打开：

| 内置层 | 初始设置 | 终局是否启用 | 作用 |
|---|---:|---:|---|
| `hand_align` | on | 是 | 按真实手数补齐/截断动作，避免位置错配 |
| `weed_repair` | on | 是 | 目标格是 WEED 时先 DIG，再尝试重放原动作 |
| `sell_lead` | on | 是 | 在无城镇消费的空档，把下一回合计划卖出的货提前卖 |
| `front_run` | off | 否 | 只有提供对手计划时才可抢先卖，终局未启用 |
| `budget_guard` | off | 否 | 每 72 步预测下一段采购所需现金并补卖 |
| `room_guard` | off | 外层重新打开 | h23 预测棚屋溢出，优先清掉未来不会卖的货 |
| `clamp_sells` | off | 否 | 按投影库存裁剪卖单 |
| `dead_stock` | off | 外层重新打开 | 卖掉路线剩余部分永远不会出售的库存 |
| `terminal_liquidation` | off | 否 | 最后一步清空棚屋；终局由包装层另行处理 |

终局 `_SETTINGS` 明确写着 `budget_guard=False`、`clamp_sells=False`、
`terminal_liquidation=False`、`front_run=False`。后面源码又把
`room_guard` 和 `dead_stock` 打开。**不能看到源码里有某个函数，就断言它
在每一局都生效**；应同时检查开关、触发条件和遥测。

| 层/标记 | 主要职责 |
|---|---|
| 终局救援包装 | 最后一步强制 DROP，再把可卖库存投影后一次性卖出 |
| `ROOMGUARD` | h23 预测棚屋容量，避免超过 100 的物品被销毁 |
| `D27` | 末期种子浮动裁剪，同时保留市场槽位顺序 |
| `S752` / `QC` | 在不破坏市场队列的前提下压缩订单 |
| `try/except` 包装 | 任何一层失败都回退到父层动作；父层失败再回退到磁带或 PASS |
| `kaggle_entry` | 显式暴露 Kaggle 实际调用的最后一个可调用对象 |

### 5.4 哪些层是“关键”、哪些只是“注册”

终局前对 60/60 个包装点做消融，得到三类结果：

* **关键承重**：`V233`、`R51_INPUT`、`R51_WAREHOUSE`、`R85`、
  `CXD`、`QC`、`FS` 等，拆掉后胜场明显下降；
* **轻度承重**：`R95`、`R127`、`seedcut`、`F29`、`D27`、`AX` 等，
  通常少 1–2 胜或只影响 margin；
* **惰性/未触发**：`R36_SALE`、`R97`、`ROOMGUARD` 等，在特定面板上
  拆掉没有变化。它们仍保留，因为可能在世界分布变化时提供保护。

这解释了一个常见误解：**“约 60 层包装点”不等于“60 次有效模型更新”。**
更准确的说法是：约 60 个可消融的包装/控制点，共同组成一个非常长的确定性
策略程序。

## 6. 三条候选的血统

```text
w2_120
  |  去掉 V92_P + V9_RACE
  v
comb
  |  V9_FERT_FIRST_DAY 14 -> 12
  |  R37_PRICE_FLOOR    1 -> 2
  |  R37_HINGE_GAIN     8 -> 6
  v
comb2b（终局主提交）
```

### 6.1 `w2_120`：路线拼接基座

`w2_120` 保留了 day-12–19 的路线 104 和 day-20–26 的路线 120，外加两个
针对活对手的市场层。它在 7 个池、1,342 局上报告净 +43 次胜负翻转；
在最新 live meta 上 +10/58，低分段没有明显退化。

这份代码被提交过两次并被完整保留：早期 ref `56697965` 曾在 public 读数
达到 2203.1；关闭提交前重发同一文件，到截止时读数为 2072.3，终局 private
为 4510.7。两个读数不能直接比较，因为新提交从基线开始爬分，且天梯环境
随时间变化。

### 6.2 `comb`：去掉两个“抢先卖”层

`comb` 相对 `w2_120` 去掉了 `V92_P` 与 `V9_RACE`。这是一个有争议的手术：
冻结回放池里，去掉这些层可以减少假想的市场攻击；线上早期 `comb_pp_race`
却停在 1943.9，说明**冻结对手不能完整代表会反应的活对手**。

### 6.3 `comb2b`：3 个常量，6 行 diff

相对 `comb`，终局只改了三个常量：

```diff
- _R37_PRICE_FLOOR = 1
+ _R37_PRICE_FLOOR = 2

- _R37_HINGE_GAIN = 8.0
+ _R37_HINGE_GAIN = 6.0

- V9_FERT_FIRST_DAY = 14
+ V9_FERT_FIRST_DAY = 12
```

三池配对证据如下：

| 候选 | 108 局面板 | 131 局真实对局池 | 76 局独立池 |
|---|---:|---:|---:|
| `comb` | +33 | −240 | +4,900 |
| `fert12` | +117（+84，t=5.10） | −158（+82，t=4.67） | +4,994（+94，t=2.47） |
| `comb2a` | +144（+111，t=5.50） | −133（+107，t=5.32） | +5,013（+113，t=2.84） |
| **`comb2b`** | **+145（+112，t=5.55）** | **−132（+108，t=5.38）** | **+5,013（+113，t=2.80）** |

这里的数字应读作“同一对手、同一世界下的配对边际”，不是普通的不同局
胜率。`V9_FERT_FIRST_DAY` 的 12 和 13 在该面板上逐局完全相同，这与
**窗口开关**的行为一致；具体水肥机制仍是待单独验证的解释，不能仅凭该结果
证明所有世界共享同一因果路径。

## 7. 终局方案是怎样被淘出来的

### 7.1 先建立可信的尺子

第一天最重要的工程不是模型，而是确认本地引擎与线上一致：4 局线上动作
逐状态重放，720 步均无首次分歧。之后我们使用三层评估：

1. **配对 A/B**：同一对手、同一世界、同一 seed 比较两个候选；
2. **保真度过滤**：对手被冻结磁带“饿死”后仍继续录像动作的局，不能把
   绝对胜率当真；
3. **多池复核**：108 局面板、131 局真实对手、76 局独立池和 996 局历史
   败局池分开报告，不把一个池的偶然结果包装成普适结论。

单局 margin 的标准差约 13,129；配对差的标准差约 201，噪声约缩小 65 倍。
这让我们能看见“只改善几十到几百资金、但不足以改变胜负标签”的真实信号。

### 7.2 先否定昂贵而错误的路线

| 问题 | 做过的实验 | 结果与决策 |
|---|---|---|
| 换一条新 tape 是否更强 | 路线拼接、固定开局、捐赠者移植、市场流混流 | 拼接/移植大多状态绑定；混流破坏现金流 |
| 增加一个动作是否能救产能 | 补喂、逃逸修复、终局携带、买地/牲畜替代 | 多数被劳动机会成本吃掉 |
| 市场微观结构是否还有空间 | 约 350 个市场流变体、303 点搜索、买卖侧重定时、算子全排列 | 模型内几十到几百金，实盘多为噪声或负 |
| 是否有漏掉的层 | 静态枚举包装点，先消融 32 层，再补齐未测的 25 层 | 60/60 覆盖；没有新税层，只有确认核心承重层 |
| 常数是否还能扫 | 约 60 个常量/阈值，双向悬崖探测 | 只有一个未取用的正向开关：施肥首日 |

### 7.3 反向工作从哪里来

顶部方案来自公开策略的研究，但我们没有直接复制一份成品当作终局：

* 开头几周先确认引擎、动作格式和回放保真度；
* 研究公开路线库与高分 write-up，理解“按商店选路线”；
* 把市场预测、卖单重排、番茄投资、羊群和劳动保护分别拆成可消融层；
* 每次只改变一个有明确语义的模块或常量；

### 7.4 四个有代表性的探索切片

**番茄线：**

1. 败局画像显示，对手在 day 20 平均有 8.0 格番茄，胜局对手只有 1.7 格；
2. 先查“我们是否完全没种”——`V219` 在 40 局探针里 39 局触发，并非零番茄；
3. 再试拓宽 15/20/25 格、提前到 day 16、放宽商店门槛、替换小麦；
   加宽和提前多为一脚踩空的局部最优，替换小麦更是切断饲料和收获链；
4. 真正缺口是“晚番茄 + 鹅 + 第四象限 + 劳动/卖单配额”的整套计划，
   不是再种几格能补齐的。由此停止用番茄补丁伪装成新架构。

**市场线：**

1. 约 350 个市场流合成变体、303 个逐点替换候选、多个买卖侧重定时；
2. 订单全排列算子可以把模型内估价提高 +47~+101，但 108 局实盘没有变化；
3. 原因是估价器拿基线订单当假想对手，真实对手会反买、反卖和改变现金流；
4. 结论是市场微结构已经进入噪声区，继续加算子只是在拟合错误的对手模型。

**施肥线：**

1. 早期扫描只数翻转：`14→12` 是 −1 胜，于是被淘汰；
2. 后来保留同一对手、同一世界，只看配对 margin：+84/局，t=5.10；
3. 阈值扫描发现 12 与 13 行为完全相同，14 恰好在窗口外；
4. 最终把它与两个 R37 常量叠加，成为整场最后一个有稳定正证据的改动。

**路线线：**

1. 先保留 41 条完整路线，避免破坏 720 步动作之间的因果链；
2. day-6 表做 52 格留一法重拟合，样本内 oracle 变好，留出集变差；
3. 27 组路线×边界联合扫描中，现役 `104/120` 最优；
4. 因此没有继续“造一条看起来聪明的路线”，而是承认这套路由的边界，
   把剩余时间投入可复现的消融、常量和配对评估。

## 8. 为什么这条路最后撞墙

### 8.1 薄市场墙

小麦、胡萝卜等基础商品的买家池较深，而牛奶、羊毛、鸡蛋等动物商品的市场
容量小。多养动物会同时增加自己的供给并压低自己的卖价；因此“加产能”
不能简单等同于“加利润”。

### 8.2 链条墙

720 步内的建造、取放、喂养、照料、收获和卖单是一本联动的账。一个看似
更好的买卖时点，可能让下一步没有现金雇人，或让工人在错误的位置完成
一个 no-op。50 多个市场/动作算子中，绝大多数都在这里失效。

### 8.3 劳动墙

终局磁带在大部分时段接近满负荷。每只牲畜每天需要喂食、照料、收集和
收获等多个动作。我们的补喂实验救回了 154 只羊，但额外劳动价值约 35k，
换来的资本约 77k，净效果仍为负。**让一部分羊逃逸不是简单的 bug，而是
固定劳动预算下的主动淘汰。**

### 8.4 真正的差距在哪里

崩盘局的关键画像不是“我们没有现金”，而是“对手在 day 12–24 持续把现金
换成活体牲畜，我们在 day 12 后把牲畜规模冻结在 17”。我们仍然有现金、
有地块，也并非完全缺工人；缺的是一套能按世界重排整份生产计划的计划级
调度器。头部 Transformer 恰好具备这种能力。

## 9. 证据中的两个矛盾，不要抹平

### 9.1 冻结回放 vs 直接对打

| 评估 | 排序 |
|---|---|
| 996 局冻结回放配对 | `comb2b > comb > w2_120`，+238/局，t=13.5 |
| 256 局沙盒直接对打 | `w2_120` 反向胜出，67–80% |
| 线上同期天梯 | `comb2b` 高于 `w2_120` |

冻结回放会把对手固定住，可能高估“市场攻击”或“去掉防守层”的价值；
直接对打又会让两个专为打别人设计的磁带互相利用对方盲点。比赛最终采用
线上 BT 重算，所以线上结果是提交决策的主要依据，但这两个测法都没有被
我们伪装成完全一致。

### 9.2 早期的胜场结论，不一定是模型结论

同一个施肥首日改动，早期用胜场计数被判为“−1 胜，惰性”；改用同局配对
margin 后得到 +84/局、t=5.10。原因是大效应落在“贴面局”的几十到几百金，
而不是把每一局从输翻成赢。**在噪声环境中，胜负标签会丢掉连续信号。**

## 12. 一句话评价

这套方案的强项是**可审计、可回退、在有限算力下非常稳定**：41 条路线
保留了完整生产链，约 60 个包装点允许局部手术，配对 margin 让我们找到了
一个被胜场判据丢掉的真信号。它的弱项是**无法在 day 12 后按世界重新规划
生产**，所以外层的市场微调最多只能把分数推到前 5.02%，无法追平会自博弈
和学习整局策略的 Transformer。

## English abstract

The final agent was a deterministic route-replay policy, not a learned neural
network. It embedded 41 complete 719-step action tapes, selected a route from
the first two unlocked shops on day 6, and forced routes 104/120/2 across the
day-12–19, day-20–26, and day-27–29 windows. Roughly 60 wrapper/control points
then adjusted opening behavior, tomato production, sheep expansion, labor,
input planning, market ordering, endgame liquidation, and failure fallback.

The final `comb2b` lineage is `w2_120 -> comb -> comb2b`: two market layers
were removed to make `comb`, then three constants were changed to form the
submission. Paired evaluation across three independent opponent pools found a
stable +108 to +113 margin per game, while a 996-game historical-loss pool
found +238 per game against `w2_120` (t=13.5). The route reached 509th of
10,148 teams and missed silver by one point; its main structural limit was
that the frozen tape did not replan production after day 12. In our evaluated
route family this was the principal bottleneck; the best public teams instead
learned state-conditioned policies, with and without PPO.
